# 管理后台 AI 运营助手设计

日期：2026-09-01

## 1. 目标与范围

在既有 `web/admin` 管理后台工作台内增加可收起的“AI 运营助手”抽屉，作为答辩可直观展示的运营决策辅助能力。它覆盖以下三个受限场景：

1. 运营数据问答：解读订单、GMV、完成率、取消率和优惠券指标。
2. 异常订单分析：识别取消、支付失败、派单超时或投诉关联的优先处理订单。
3. 风控审核助手：汇总高风险命中记录，给出人工复核建议与可核查证据。

本期以稳定、可解释、可重复演示为优先级，不训练预测模型，不改变订单、风控、审核等核心业务状态，不替代人工决策。

## 2. 设计原则

- 事实优先：订单、统计和风控结论只来自既有后台结构化查询或固定演示快照，LLM 只负责理解问题、选择工具、组织解释和建议。
- 最小权限：模型不能生成 SQL，不能访问数据库，不能调用冻结、退款、拉黑、发布活动等写接口。
- 人工确认：回答的动作只可跳转既有详情页面或预填操作草稿；真实动作仍经现有权限、状态机、幂等和审计链路。
- 数据脱敏：不向外部模型传递完整手机号、身份证号、精确地址、完整敏感备注或鉴权信息。
- 明确降级：回答必须标识 `realtime`、`demo_snapshot` 或 `template_fallback` 数据来源，演示快照绝不伪装为实时业务数据。

## 3. 架构与目录边界

不新建微服务。前端入口位于既有管理后台工作台，HTTP 层保持 `api/admin` 的鉴权和参数职责，AI 编排封装在 `rpc/adminsvc` 内部隔离模块。

```text
web/admin 工作台 AI 抽屉
        |
api/admin /admin/v1/ai-agent/*
        |
rpc/adminsvc 内部 aiagent 模块
  |-- 场景路由与权限校验
  |-- 白名单只读工具
  |-- 数据脱敏、提示词和响应校验
  |-- 演示快照与本地模板降级
  |-- 外部 LLM 客户端
        |
既有 adminsvc / ordersvc / driversvc 查询能力
```

建议新增的实现边界如下，具体文件名在实施计划中再按现有 go-zero 风格细化：

| 位置 | 职责 |
| --- | --- |
| `web/admin/src/views/console` 或独立 AI 抽屉组件 | 快捷问题、提问、分块渲染、来源标识、详情跳转与反馈 |
| `api/admin` | 会话鉴权、请求参数校验、调用 adminsvc、统一 JSON 响应 |
| `rpc/adminsvc/internal/logic/aiagent` | 场景编排、工具白名单、脱敏、模型调用、降级和审计 |
| `rpc/adminsvc/internal/aiagent` | 不依赖 RPC 传输层的模型客户端、提示词、工具定义、快照与模板报告 |
| `rpc/adminsvc/etc/admin.yaml` | 外部模型地址、模型名、超时、演示模式开关；密钥只从环境变量读取 |

`agent/react` 是当前仓库已有的通用 Agent 骨架，可作为工具调用设计参考；本期不将后台业务逻辑耦合到命令行示例程序。

## 4. 场景与界面契约

工作台右侧提供“AI 运营助手”入口和可收起抽屉，顶部显示三个快捷入口，下面支持受限自由提问。回答固定渲染为四个区域，以保证即使模型语言波动，答辩界面也稳定：

1. 结论：一句话说明主要趋势或风险。
2. 数据证据：指标、时间范围、原因分布和来源。
3. 优先对象：最多三条订单或风控记录，显示编号、等级、触发因素和详情跳转。
4. 建议动作：只提供页面跳转或草稿，不直接执行写操作。

| 场景 `scene` | 快捷问题 | 查询事实 | 可跳转页面 |
| --- | --- | --- | --- |
| `overview` | 分析今日运营风险与增长机会 | 运营总览、订单统计、收入/用户/优惠券统计 | 统计页、活动配置页 |
| `abnormal_order` | 识别需要优先处理的异常订单 | 异常订单、订单详情可得的派单/支付/状态信息 | 异常订单页、订单详情、工单页 |
| `risk_review` | 总结待复核高风险命中并给出建议 | 风控命中、黑名单状态、司机/订单关联摘要 | 风控命中页、黑名单页、司机审核页 |

自由问题仅限上述三个场景。无法分类或超出后台业务范围的问题返回范围提示，不作为开放式聊天机器人处理。

## 5. 受控工具和数据流

模型可提出工具调用请求，但工具名、参数和返回字段全部由服务端白名单控制：

| 工具 | 可用场景 | 数据来源 | 约束 |
| --- | --- | --- | --- |
| `query_operating_metrics` | `overview` | 既有统计 RPC | 固定合法统计维度与最长时间范围 |
| `list_abnormal_orders` | `abnormal_order` | 既有异常订单查询 | 每次最多返回三条优先对象及聚合摘要 |
| `get_risk_hit_summary` | `risk_review` | 既有风控命中与黑名单查询 | 只返回脱敏对象标识、命中类型、次数和处置摘要 |
| `load_demo_snapshot` | 三个场景 | 只读内置快照 | 仅本地或答辩环境且显式开启时可用 |

处理步骤：

1. API 层验证管理员会话、场景、问题长度、时间范围和演示权限。
2. adminsvc 根据场景构建允许工具集合，读取结构化事实并脱敏。
3. 编排层向 LLM 提供场景说明、工具结果和严格 JSON 输出协议；不提供数据库连接、Token、原始业务对象或写操作工具。
4. 服务端校验模型输出中的证据 ID 和跳转对象必须来自本次工具结果；无依据的对象或建议将被丢弃。
5. 输出标准化结构，写入仅含摘要的审计记录后返回前端。

模型输出不是业务真相。统计值、订单编号、风险级别和处置状态由服务端结构化结果覆盖或校验，模型不得凭空补充。

## 6. HTTP 与响应契约

V1 仅新增下列后台接口，保持既有 `/admin/v1` 路径、Bearer Token 和统一响应包装。

| 接口 | 说明 |
| --- | --- |
| `POST /admin/v1/ai-agent/ask` | 提交一个受限问题并返回结构化回答；可携带 `conversation_id` 延续多轮 |
| `GET /admin/v1/ai-agent/suggestions` | 读取当前管理员可见的三个快捷问题 |
| `GET /admin/v1/ai-agent/history` | 查询当前管理员自己的会话列表及每会话问答摘要 |
| `POST /admin/v1/ai-agent/feedback` | 记录回答是否有帮助，用于后续提示词和工具评估 |
| `DELETE /admin/v1/ai-agent/conversations/{id}` | 结束并清空指定会话（仅本人） |

`ask` 请求：

```json
{
  "scene": "abnormal_order",
  "question": "识别今天需要优先处理的异常订单",
  "conversation_id": "conv_8f3a2b1c",
  "start_time": "2026-09-01 00:00:00",
  "end_time": "2026-09-01 23:59:59",
  "demo_mode": true
}
```

`demo_mode` 仅允许部署配置开启的本地/答辩环境，生产配置必须拒绝该字段。响应由服务端结构化输出，前端不直接渲染模型原文：

```json
{
  "summary": "晚高峰派单等待超时导致取消率上升，建议优先复核 3 笔订单。",
  "evidence": [
    {"label": "取消率", "value": "18.6%", "comparison": "较昨日 +8.6%"}
  ],
  "priorities": [
    {"type": "order", "id": "202609010001", "level": "high", "reasons": ["派单超时", "重复取消"], "route": "/orders/202609010001"}
  ],
  "actions": [
    {"type": "navigate", "label": "查看异常订单", "route": "/orders/abnormal"}
  ],
  "source_mode": "demo_snapshot",
  "citations": ["异常订单快照：晚高峰场景"],
  "conversation_id": "conv_8f3a2b1c",
  "trace_id": "..."
}
```

## 7. 多轮会话设计

V1 支持受限多轮追问，但仍约束在单一场景内，不开放为通用聊天。

### 7.1 会话模型

- 会话是管理员的私有一等实体，并绑定单一 `scene`。三个场景的工具白名单不同，跨场景追问需切换会话或新建会话；同一会话内场景固定，服务端校验 `conversation_id` 与 `scene` 一致，不一致则拒绝。
- 生命周期：
  1. 创建：`ask` 不带 `conversation_id` 时由服务端创建并返回；
  2. 延续：后续 `ask` 携带 `conversation_id` 与相同 `scene`；
  3. 过期：默认 24 小时无活动自动失效（与管理员登录 TTL 对齐，可配置）；
  4. 结束：管理员显式清空，或切换场景自动视为新会话。

### 7.2 上下文管理

- 每个会话只保留最近 N 轮（默认 6 轮）对话。每轮保留：用户问题、场景、本轮工具调用摘要、服务端最终结构化回答（均已脱敏）。
- 不保留工具全量原始结果，只保留脱敏后的证据 ID、聚合值与优先级对象摘要，避免敏感数据累积与上下文膨胀。
- 双预算：单轮输入 token 上限 + 会话累计 token 上限；超限按 FIFO 截断最早轮次，并向模型注入"更早上下文已省略"标记，防止模型对缺失上下文产生幻觉。

### 7.3 指代与事实刷新（关键约束）

- 允许模型理解跨轮指代（如"那第 2 单呢""取消率比昨天如何"）。
- 但每轮回答引用的证据 ID、优先级对象必须来自本轮工具调用结果，不允许沿用上一轮旧证据 ID（数据可能已变化）。模型可引用上一轮结论做对比，但新事实必须重新查询并重新校验。
- 该约束沿用第 5 节"模型输出不是业务真相"的原则：多轮只扩大上下文窗口，不放松反幻觉校验。

### 7.4 接口契约

- `ask` 请求新增可选 `conversation_id`，缺省创建新会话；响应始终返回当前 `conversation_id`。
- 新增 `DELETE /admin/v1/ai-agent/conversations/{id}`：结束并清空指定会话（仅本人）。
- `history` 改为按会话聚合：返回会话列表，每会话含最近问答摘要与来源模式。

### 7.5 存储与隔离

- 热上下文存 Redis，独立前缀（如 `admin:ai:conv:`），带 TTL，与现有 `admin:sess:` 隔离。
- 脱敏审计摘要落库（问题哈希、场景、工具名、来源模式、结果摘要），不落原始问题全文。
- 会话严格归属管理员本人，读/清空/历史均按 `ai:insight:view` 与归属校验。

### 7.6 降级与多轮

- `template_fallback` 与 `demo_snapshot` 均按本轮事实生成，不依赖历史上下文即可完整产出。
- 演示快照中订单号、风险命中 ID 固定不变，保证跨轮引用稳定可复现。

## 8. 演示快照和降级

演示快照应以版本化只读 JSON 或 Go 嵌入资源保存，包含三个场景各一份固定事实、优先对象、预期证据和本地模板报告。快照只用于演示环境，不能写回现有业务表，也不能参与真实生产处置。

降级顺序如下：

1. 真实业务查询 + 外部 LLM。
2. 真实业务查询 + 本地模板报告：模型超时、限流、无效 JSON 或回答缺乏依据时使用。
3. 演示快照 + 外部 LLM：仅允许的答辩环境。
4. 演示快照 + 本地模板报告：答辩网络或模型 API 不可用时保证可完整演示。

生产环境的真实查询失败必须返回明确错误，禁止自动转用快照伪造线上结论。前端将 `source_mode` 显示为“实时数据”“演示快照”或“本地规则报告”。

## 9. 安全、权限和审计

- 复用后台管理员会话校验；AI 入口应有独立只读权限，例如 `ai:insight:view`。
- 按已有敏感数据规则脱敏；模型输入只携带展示所需的订单号、状态、计数、金额区间、风险类型和聚合指标。
- 不记录外部模型密钥、Bearer Token、完整敏感原文和精确位置。模型供应商地址、模型名、超时和开关配置化，密钥从环境变量注入。
- 审计记录包含管理员 ID、场景、问题摘要/哈希、工具名、来源模式、结果摘要、trace ID、耗时、模型调用是否成功和错误类别。
- 历史记录默认仅允许提问管理员本人查询；具备审计权限的管理员仅能查询必要摘要。
- 所有详情跳转仍由目标页面重新执行原有鉴权，AI 回答不能成为越权访问凭证。
- 多轮上下文只保留脱敏摘要，热上下文 TTL 过期即清；会话读/清空/历史严格归属本人，避免通过会话上下文横向获取他人敏感数据。

## 10. 可靠性和错误处理

| 情况 | 行为 |
| --- | --- |
| 模型超时、限流、网络失败 | 基于已经核验的事实生成本地模板报告，并标识 `template_fallback` |
| 真实工具查询失败 | 生产环境返回可识别错误；答辩环境在已启用快照时进入快照链路 |
| 模型请求未授权工具 | 服务端拒绝调用并记录安全事件摘要 |
| 模型响应非结构化或字段非法 | 尝试一次受限修复；仍失败时使用模板报告 |
| 模型引用不存在的订单或风险记录 | 丢弃该对象；无有效证据时降级为范围说明 |
| 超范围问题 | 返回支持范围，不调用模型进行开放闲聊 |

调用应设置上下文超时、请求大小限制和每管理员限流，避免答辩演示或普通使用影响既有后台接口。

## 11. 测试与答辩验收

单元测试覆盖：场景校验、工具参数白名单、数据脱敏、演示权限、模型 JSON 校验、无依据对象过滤、四级降级、多轮上下文截断与 token 预算、会话场景绑定校验和审计摘要。

API 测试覆盖：未登录、无 AI 权限、非法场景、超长问题、生产环境 `demo_mode=true`、模型失败降级、多轮延续（含 `conversation_id` 与 `scene` 不一致拒绝）、会话清空与过期、历史隔离和反馈参数校验。

前端测试覆盖：三个快捷入口、回答四分区渲染、来源标识、详情跳转和失败状态。

答辩验收标准：

1. 三个快捷场景均可在固定演示数据下稳定复现。
2. 每个结论都有结构化证据、数据来源标识和至少一个现有页面跳转。
3. 断开模型 API 后，三个场景仍能通过本地模板完整演示。
4. 任意建议均不能直接变更订单、司机、黑名单、活动或退款状态。
5. 可展示一次工具调用与审计摘要，说明模型受控、可追溯且不越权。
6. 可演示至少一次跨轮追问（如"那第 2 单呢"），且追问回答引用的证据仍来自本轮重新查询。

## 12. RAG 与智能分析演进

V1 的数据源以结构化事实和演示快照为主。后续演进保持 Agent 对话接口和工具边界不变，只增加知识检索工具：

```text
管理员问题
  -> AI 编排
     -> 结构化查询工具：实时指标、异常订单、风险命中
     -> 演示快照：答辩兜底
     -> 知识检索工具：V2 接入 RAG
```

| 阶段 | 能力 | 数据来源 | 典型问题 |
| --- | --- | --- | --- |
| V1 答辩版 | 三场景、受限问答、快照降级 | 既有查询与固定快照 | 今日取消率为何上升？ |
| V1.1 运营版 | 会话、反馈、工具审计与提示词评估 | 真实结构化查询 | 近 7 天高风险订单有哪些共性？ |
| V2 RAG 版 | 带引用的知识检索与案例归纳 | 规则制度、接口口径、活动规则、脱敏工单案例 | 这种命中应依据什么规则处理？ |
| V3 分析版 | 结构化分析 Agent 与离线特征 | RAG、白名单聚合、离线报表 | 活动转化下降与哪些因素相关？ |

RAG 只承担规则、制度、口径和脱敏历史案例的检索增强；实时 GMV、订单状态和风险命中必须继续由结构化查询工具获得。向量库中的文档需分段、版本化、标注来源和脱敏，回答必须携带可见引用。不得将线上用户、司机、订单明细整库向量化，以避免敏感泄漏、索引陈旧和事实错误。

## 13. 非目标

- 不在本期引入数据库结构变更、向量数据库、模型训练或在线预测模型。
- 不开放通用聊天、任意 SQL、文件上传、自动执行后台敏感操作或跨服务写入。
- 不修改既有订单、风控、司机审核、活动发布和退款业务契约。
