# 管理后台五项问题一次性收口设计

## 1. 背景与目标

图片中的管理后台问题包含前端路由复用、复杂业务表单、后端路由文件过大、订单详情信息不完整、统计接口未可视化五项。本设计基于当前代码、`README.md`、管理后台设计文档、HTTP/RPC 接口文档和现有数据库定义，在不改变已开放接口契约、不修改数据库结构和不污染业务数据的前提下完成一次性收口。

## 2. 范围

### 2.1 包含范围

1. 将 `web/admin/src/router/index.js` 中指向通用控制台页面的业务路由改为真实业务页面。
2. 为已有管理后台接口提供按业务域组织的页面入口，并复用现有 API 封装和权限信息。
3. 对优惠券、计价规则、营销活动等复杂配置提供分组字段、校验、提交中和错误状态。
4. 在订单详情页增加用户历史订单和用户优惠券两个独立数据区块，使用已有接口并支持懒加载失败降级。
5. 将统计接口接入运营总览页面，展示订单趋势、司机指标、收入指标和优惠券指标，并提供空数据/请求失败状态。
6. 将 `api/admin/internal/handler/router.go` 的路由注册按业务域拆分为多个文件，由 `NewRouter` 统一组装；对外路径、方法、中间件、鉴权和响应行为保持不变。
7. 增补与本次行为相关的前端构建验证、后端路由映射测试和数据转换测试。

### 2.2 不包含范围

- 不新增数据库表、字段、索引或迁移脚本。
- 不改变 `rpc/adminsvc/admin.proto`、HTTP 接口路径、请求参数、响应字段和权限语义。
- 不实现设计文档中尚未开放的规划接口。
- 不重写既有业务逻辑，不迁移服务边界，不更换 Vue/Go 技术栈。

## 3. 现状与问题映射

### 3.1 前端路由与页面

当前多个菜单路由统一进入 `console/index.vue`。该页面适合简单列表和通用配置，但不能表达订单、司机审核、优惠券、营销活动和工单等页面的独立交互状态。

### 3.2 复杂表单

优惠券需要类型、门槛、面额/折扣、有效期和限领等字段；营销活动需要活动类型、JSON 配置、发布范围和状态流转；计价规则需要步进价、里程费、时长费等结构化参数。页面必须在提交前完成字段校验，并将后端错误展示给用户。

### 3.3 后端路由组织

`api/admin/internal/handler/router.go` 集中承载大量路由注册与处理函数绑定。此次只调整文件组织，不调整路由注册顺序和运行时行为。

### 3.4 订单详情

订单主信息、取消、改派、退款、轨迹能力已存在，但用户历史订单和优惠券接口未在详情页展示。关联区块应独立请求，避免关联服务失败阻断订单主信息。

### 3.5 统计可视化

后台已经提供 overview、orders、drivers、revenue、coupons 等统计接口，但控制台未将其转换为趋势图和指标图表。首版只消费已有接口返回数据，不引入新的聚合存储。

## 4. 方案设计

### 4.1 前端页面与路由

按现有目录约定在 `web/admin/src/views` 下组织业务页面：用户、司机、订单、优惠券、计价规则、营销活动、风控、操作日志、导出任务和工单。路由元信息保留菜单名称、权限码和布局行为；未开放或无独立交互的页面继续使用控制台入口，但不得把已有复杂业务页面隐藏在通用渲染器中。

页面统一使用 `src/api/modules.js`、`src/api/auth.js` 和现有请求封装。列表页面具备加载、空数据、错误和分页状态；操作按钮依据后端鉴权结果和现有权限码展示。

### 4.2 复杂业务表单

优先扩展 `BusinessFormDialog.vue` 的字段配置能力，必要时由优惠券、计价规则和营销活动页面提供专用字段分组。表单提交保持原接口请求体字段定义；JSON 配置字段在前端检查合法 JSON，后端校验错误原样转为统一错误提示。提交期间禁用重复提交，成功后刷新列表并关闭弹窗。

### 4.3 订单详情关联数据

订单详情加载顺序为：先请求订单主详情，成功后根据 `user_id` 并行懒加载用户历史订单和用户优惠券。关联区块各自维护 loading、empty、error 状态；任一区块失败只显示可重试提示，不影响取消、改派、退款和轨迹等既有能力。字段映射严格遵循管理后台接口文档，不从数据库直接读取。

### 4.4 统计图表

运营总览请求统计接口并将返回值转换为图表模型。展示内容包括：订单趋势/完成率、司机数量与活跃指标、收入趋势/GMV、优惠券发放与使用率。图表组件使用项目已有依赖或最小化新增前端依赖；若无需复杂交互则采用轻量 SVG/Canvas 图表封装。接口失败时保留可用指标卡，图表显示空状态和重试入口，不伪造数据。

### 4.5 后端路由拆分

新增按业务域命名的 handler 注册文件，例如认证管理员、用户、司机、订单、营销、统计风控和导出工单等。每个文件只负责将现有路径绑定到现有处理方法；`router.go` 负责创建根路由、中间件和调用各模块注册函数。拆分后通过现有全量路由冒烟测试，保证 HTTP 方法、路径参数、鉴权和状态码不变。

## 5. 错误处理与兼容性

- 所有后端错误继续使用当前统一响应格式和错误码映射。
- 前端请求失败显示后端 `message`，不吞掉鉴权失败和业务校验错误。
- 关联信息和统计图表采用分块降级，主页面不可因非核心请求失败而白屏。
- 不执行任何数据库迁移、写入、回填或数据修复操作。
- 保留工作区中与本任务无关的已有修改，不回退用户代码。

## 6. 验收标准

1. 业务菜单进入对应独立页面，不再全部落到 `console/index.vue`。
2. 优惠券、计价规则、营销活动表单能够展示文档规定字段，完成前端校验、提交、错误提示和成功刷新。
3. 订单详情能展示用户历史订单和优惠券；关联接口失败时主订单信息仍可用。
4. 运营总览能加载五类统计接口并显示至少四组图表/指标，空数据和失败状态可识别。
5. `router.go` 拆分后全量路由冒烟测试通过，外部 API 行为无变化。
6. `web/admin` 执行 `npm run build` 成功；`go test ./api/admin/... ./rpc/adminsvc/...` 通过。

## 7. 实施顺序

1. 先拆分后端路由并运行现有路由测试，建立行为基线。
2. 调整前端路由和页面入口，复用现有 API 与通用组件。
3. 补齐复杂表单状态和校验。
4. 扩展订单详情关联区块。
5. 接入统计图表并补充数据转换测试。
6. 执行前端构建、后端测试和必要的页面冒烟验证。
