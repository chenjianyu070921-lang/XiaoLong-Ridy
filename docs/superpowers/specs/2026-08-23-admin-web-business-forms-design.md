# 管理后台业务字段化表单设计

## 目标

将 `web/admin` 中统一工作区的任意 JSON 输入改为受控、字段化的业务表单；保持既有 HTTP 接口、鉴权、RPC 边界和数据库结构不变。

## 范围

本次仅修改 `web/admin`。覆盖所有当前已开放写操作：优惠券创建/编辑/停用/发券，计价规则创建/编辑/启停，营销活动创建/编辑/发布/回滚，工单创建/流转/证据，黑名单新增/解除，导出任务创建，用户冻结/解冻，司机认证通过/驳回，订单取消。

不新增后端接口，不修改 API 请求字段，不修改数据库或业务数据；未开放的人工改派、退款、司机冻结等能力不在本次范围内。

## 架构

新增 `web/admin/src/components/BusinessFormDialog.vue`，作为唯一写操作弹窗。它接收业务表单类型、初始记录和提交回调，内部按表单类型渲染具名字段、执行前端校验，并输出与当前 API 客户端一致的请求体。

`views/console/index.vue` 保留路由判断、列表加载、详情加载和接口选择；写操作只负责声明表单类型、传入当前行和调用已存在的 `modules.js` 方法。删除 `form.payload` 与任意 JSON 解析逻辑。

详情视图新增字段分组展示组件或局部映射：基础信息、状态信息、时间信息和关联信息以标签和值形式展示。仅后端返回且没有稳定业务结构的只读配置字段可使用格式化文本展示，不作为可编辑 JSON 输入。

## 表单与请求映射

| 表单 | 字段 | 请求约束 |
| --- | --- | --- |
| 优惠券 | 名称、类型、面额、折扣、门槛、库存、单人限领、有效期、状态 | 金额保持字符串；开始时间早于结束时间；库存与限领为正整数。 |
| 发券 | 目标类型、用户 ID 列表 | 当前只允许显式用户；逗号或换行分隔的正整数转换为 `target_config: {"user_ids":[...]}` 字符串。 |
| 计价规则 | 名称、城市编码、车型、起步价、起步里程、每公里价、每分钟价、夜间时段、夜间加价、动态上限、生效期、状态 | 金额和里程保持字符串；时间按既有 `YYYY-MM-DD HH:mm:ss` 传递。 |
| 营销活动 | 名称、类型、开始/结束时间、状态、配置内容 | 配置内容使用受控多行文本并校验 JSON，仅写入现有 `config` 字段；其余字段使用控件。 |
| 工单 | 工单类型、来源类型/ID、订单/用户/司机 ID、标题、内容、优先级 | 可选关联 ID 为非负整数；创建请求严格输出 `WorkOrderRequest` 字段。 |
| 工单流转 | 动作、处理人 ID、处理内容、仲裁结论、版本 | 动作限制为 `assign`、`follow`、`arbitrate`、`close`、`reopen`；版本从详情数据带入。 |
| 工单证据 | 证据类型、证据 URL、说明 | 类型限制为 `track`、`audio`、`chat`、`payment`、`image`、`text`。 |
| 黑名单 | 目标类型、目标 ID、原因 | 类型限制为 `user`、`driver`、`device`；不展示未被实际接口接受的过期时间。 |
| 导出任务 | 导出类型、开始时间、结束时间、用户/司机/订单/管理员 ID、城市编码 | 支持类型限定为后端已开放的 `users`、`drivers`、`orders`、`operation_logs`、`statistics`；字段由前端组装为 `filters` JSON 字符串。 |
| 冻结、解冻、取消、解除 | 原因、备注（后端支持时） | 原因必填；用户冻结/解冻与订单取消保留 `reason`、`remark` 契约，解除黑名单仅提交 `reason`。 |
| 司机审核 | 审核备注 | 备注字段提交至既有通过/驳回接口。 |
| 发布、回滚、启停、停用 | 无额外字段或固定受控参数 | 保持当前接口的固定 `publish_scope` 与 `target_config`，不向用户暴露任意 JSON。 |

## 错误处理与交互

前端使用 Element Plus 表单规则阻止必填、数字、日期范围和 JSON 配置错误。提交期间禁用重复提交；成功后关闭弹窗并重新拉取列表或详情。后端返回的 `40001`、`403`、`409` 等错误继续由统一 Axios 客户端提示，状态冲突后重新读取服务端数据。

## 验收

1. 前端不再出现“请求 JSON”或 `JSON.parse(form.payload)`。
2. 每个已开放写操作均通过具名字段填写、校验并发送既有请求体。
3. 详情不再以整段 JSON 直接呈现，基础字段可读、分组展示。
4. `npm run build` 成功；不修改 `api/admin`、`rpc/adminsvc`、迁移脚本或数据库。
