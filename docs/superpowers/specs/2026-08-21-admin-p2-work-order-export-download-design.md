# 管理后台 P2 工单与导出下载设计

## 范围

本轮补齐管理后台两项 P2 骨架能力：投诉/申诉工单后台人工处理，以及已生成导出文件的受控下载。变更仅涉及 `api/admin` 与 `rpc/adminsvc`，复用已落库的 `admin_complaint_work_order`、`admin_work_order_flow`、`admin_work_order_evidence` 与 `admin_export_task` 表，不新增或修改数据库结构。

本轮不接入乘客端投诉提交、文件上传、对象存储或跨服务工单自动创建；证据仅保存已存在资源的 URL 或文本索引。

## 工单接口与状态机

新增 RPC 与 HTTP 接口：创建、列表、详情、分配、跟进、仲裁、结案、添加证据、查询证据。HTTP 前缀为 `/admin/v1/work-orders`。

工单状态仅允许按下列动作流转：

- `assign`：`1 待处理 -> 2 跟进中`，指定 `assignee_id`。
- `follow`：保持 `2 跟进中`，记录处理内容。
- `arbitrate`：`2 跟进中 -> 3 仲裁完成`，必须填写仲裁结果。
- `close`：`3 仲裁完成 -> 4 已结案`，写入关闭时间。
- `reopen`：`4 已结案` 或 `5 已关闭 -> 2 跟进中`，清空关闭时间。

创建时状态固定为 `1 待处理`，同时写入一条 `create` 流转记录。每次状态动作在同一 SQL 事务内条件更新 `version` 并插入 `admin_work_order_flow`；版本不匹配或状态不符合时返回 `Aborted`，避免多人覆盖处理结果。添加证据要求工单存在，但不改变状态。

管理员角色沿用现有拦截器：超级管理员拥有所有工单操作；运营可创建、查询、分配、跟进、添加证据；客服可查询、跟进、添加证据；仲裁、结案、重开限超级管理员。所有写操作复用事务操作日志。

## 导出下载

新增 `GET /admin/v1/export-tasks/{task_no}/download`，位于现有 `authRequired` 之后。网关从会话取得管理员 ID 与角色，调用新增的 adminsvc 受控任务查询 RPC；RPC 返回任务状态、创建人、相对文件名和过期时间，但不返回服务内文件绝对路径给 HTTP JSON 接口。

下载前必须满足：任务存在、状态为 `success`、未超过 `expires_at`、且当前管理员为任务创建人或超级管理员。否则分别返回 `404`、`409`、`410`、`403`。网关校验任务文件名仅为 `<task_no>.csv`，再从受控 `.tmp-admin-exports` 目录以流式方式输出 `text/csv` 和 `Content-Disposition: attachment`；不接受客户端提供路径，不暴露 `file_path`。

现有导出详情和列表仍可查看任务状态，但不再返回内部 `file_path`。创建成功仍将 `expires_at` 设为 7 天。

## 过期清理

adminsvc 增加受控过期清理逻辑：每次导出成功后查询 `expires_at <= now` 且文件路径非空的任务，仅删除受控导出目录内且文件名匹配任务号的 CSV，然后清空 `file_path` 与 `file_url`，保留任务、筛选条件和失败信息用于审计。删除失败保留任务，待下一次成功生成导出时重试。该策略仅适用于当前单实例本地文件模式；多实例部署前应迁移到对象存储预签名 URL。

## 验证

工单 SQL mock 测试覆盖创建和流转事务、非法状态转换、乐观锁冲突、证据归属；网关测试覆盖路由、会话管理员参数透传。下载测试覆盖创建者下载、超级管理员下载、越权拒绝、未完成/过期拒绝、路径穿越拒绝和 CSV 响应头。导出清理测试覆盖只删除受控且已过期的文件。
