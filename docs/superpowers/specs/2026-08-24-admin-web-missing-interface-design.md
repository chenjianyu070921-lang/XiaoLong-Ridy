# 管理后台前端接口补齐设计

## 目标与范围

仅在 `web/admin` 补齐已注册但尚未形成完整前端入口的五项能力：管理员注册、当前管理员信息刷新、导出文件下载、工单证据列表和异常订单侧栏入口。

不修改 `api/admin`、`rpc/adminsvc`、数据库结构、迁移脚本或已有接口出入参。

## 页面与数据流

### 管理员注册

登录页新增注册入口，注册页使用 `username`、`password`、`real_name` 和 `role` 字段调用 `POST /admin/v1/auth/register`。注册成功后复用返回的 token 和管理员资料写入 Pinia，并跳转工作台。

首个管理员可匿名注册；后续注册是否允许由服务端超级管理员校验决定。前端不在页面层伪造权限判断，服务端返回无权限时由统一请求层提示。

### 当前管理员信息

应用启动后若本地存在 token，调用 `GET /admin/v1/auth/me`，用响应覆盖本地缓存中的管理员资料。会话失效继续由现有 Axios 拦截器清理 token 并返回登录页；请求未完成前不修改既有菜单加载流程。

### 导出下载

导出任务详情页在任务状态满足可下载条件时提供下载图标按钮。前端以当前 Bearer Token 请求 `GET /admin/v1/export-tasks/{task_no}/download`，读取 Blob、从响应文件名或任务号生成 CSV 下载文件，并及时释放浏览器对象 URL。失败沿用统一接口错误提示。

### 工单证据列表

工单详情页增加证据记录区块，调用 `GET /admin/v1/work-orders/{id}/evidence` 并使用真实分页字段展示证据类型、地址、说明和创建时间。新增证据成功后同时刷新详情及证据列表；列表加载失败显示局部错误，不影响工单主详情与流转操作。

### 异常订单入口

在静态兜底菜单和后端菜单路径映射中添加 `/orders/abnormal`。继续复用现有异常订单路由和列表调用，不新增后端请求或平行页面。

## 结构与约束

新增独立注册页和工单证据列表局部组件（或等价局部状态），避免继续放大 `console/index.vue` 的职责。导出下载封装在 `src/api/modules.js`，认证状态刷新封装在用户 Store，使页面不直接操作令牌和底层请求。

新增代码以中文注释说明请求字段、会话刷新、流式下载和局部错误处理。不得将 token、密码、MySQL DSN 或服务端导出文件路径写入页面、日志或仓库。

## 验收

1. 登录页可进入注册页，注册成功后进入工作台，非首个管理员的越权注册显示后端错误。
2. 刷新已登录页面会调用 `/auth/me` 并更新管理员显示信息；失效 token 自动返回登录页。
3. 已完成导出任务可下载 CSV，前端不暴露服务端文件路径。
4. 工单详情可显示、分页刷新证据记录，新增证据后列表同步刷新。
5. 异常订单可由侧栏直接进入。
6. `npm run build` 成功，且仅变更 `web/admin` 与本设计文档。
