# 管理后台用户历史与司机列表前端设计

## 目标

在不修改其他同事负责服务的前提下，为管理后台补齐用户订单历史、用户优惠券历史和司机列表前端预置；并对已实现的后台模块进行回归验收。

本轮只修改 `api/admin`、`rpc/adminsvc` 与 `web/admin`。不修改 `rpc/driversvc`、`rpc/ordersvc`、`rpc/usersvc`，不修改数据库结构或业务数据。

## 范围

新增只读 HTTP 接口：

| 接口 | 下游服务 | 参数 |
| --- | --- | --- |
| `GET /admin/v1/users/{id}/orders` | `ordersvc.ListOrders` | `status`、`page`、`page_size` |
| `GET /admin/v1/users/{id}/coupons` | `usersvc.ListMyCoupons` | `status`、`page`、`page_size` |

订单接口复用现有按 `user_id` 分页查询能力。优惠券接口复用现有用户券查询，由 `adminsvc` 完成后台分页、响应映射和错误适配，不改变 usersvc 的乘客端协议。

司机列表只实现前端菜单、路由、筛选、分页、详情入口和“司机服务未接入”状态；不调用或修改 `driversvc`。待该模块提供稳定后台只读接口后，仅替换前端请求封装。

## 架构与安全

请求链路固定为 `web/admin -> api/admin -> adminsvc -> ordersvc/usersvc`。网关不直连业务数据库；`adminsvc` 保留会话校验、RBAC、分页参数归一化和响应映射职责。

用户历史查询为客服可访问的只读能力，沿用用户详情和订单详情的最小权限范围。请求必须通过现有 token 校验和服务端授权拦截器。查询不写操作日志，不更新任何业务状态。

## 前端交互

用户详情页增加“订单历史”和“优惠券历史”页签。每个页签独立加载、分页和按状态筛选，空结果正常显示。订单展示订单号、地址、状态、预估金额和下单时间；优惠券展示名称、类型、面值/折扣、状态、领取时间和到期时间。

司机列表前端不返回模拟记录；接口未接入时显示明确状态，不影响其他管理页面。

## 错误处理

- 用户 ID、状态、分页非法时返回 `40001`。
- 登录失效返回 `40004`，无权限返回 `40003`。
- 下游服务不可用时返回明确的不可用错误，不伪造空数据。
- 空结果返回正常空分页响应。

## 验收

1. 覆盖用户订单和优惠券历史的参数校验、分页、状态过滤、下游错误与权限测试。
2. 验证用户详情双页签的筛选、分页、空状态与错误状态。
3. 验证司机列表前端菜单、路由和未接入状态。
4. 回归管理员认证与 RBAC、用户冻结/解冻、订单、营销、风控工单、统计和导出下载。
5. 执行相关 Go 测试和 `web/admin` 构建。

## 非目标

本轮不实现司机真实列表或冻结、订单轨迹、人工改派、退款、收入/司机/用户统计和全局用户券记录。这些功能分别依赖司机、位置、派单、支付或用户服务，应在对应模块契约稳定后单独设计。
