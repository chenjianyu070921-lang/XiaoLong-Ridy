# 管理后台统计查询保护设计

## 1. 目标

在不新增报表服务、不修改数据库结构的前提下，统一管理后台六类统计接口的查询边界，避免城市口径失真和超大时间范围实时聚合造成数据库压力，并向前端提供明确的数据生成时间。

## 2. 适用接口

以下接口继续使用现有路径和 RPC：

- `/admin/v1/statistics/overview`
- `/admin/v1/statistics/orders`
- `/admin/v1/statistics/drivers`
- `/admin/v1/statistics/revenue`
- `/admin/v1/statistics/coupons`
- `/admin/v1/statistics/users`

## 3. 查询契约

- `city_code` 非空时统一返回 `40001`，不推断城市、不静默忽略。
- `start_time`、`end_time` 使用 `2006-01-02 15:04:05` 格式。
- 未传时间时默认最近 30 天。
- 只传一个时间时，另一端按默认边界补齐：缺少开始时间使用当前时间减 30 天，缺少结束时间使用当前时间。
- 时间范围最长 90 天，超过时返回 `40001`。
- 结束时间早于开始时间返回 `40001`。
- 任一时间晚于当前时间返回 `40001`。
- 统计查询使用统一解析后的时间，不允许各指标自行采用不同默认值。

## 4. 响应字段

六个统计响应均新增：

- `generated_at`：本次查询完成时间，格式 `2006-01-02 15:04:05`；
- `data_as_of`：本次统计数据截至时间，取统一查询结束时间，未传结束时间时为当前时间。

原有指标字段保持兼容，新增字段只追加 proto 编号，不改变已有字段编号。

## 5. 实现边界

在 `adminsvc` 增加统一 `normalizeStatisticsRequest`，所有统计逻辑入口先调用该函数，再执行原有 SQL 聚合。API 层继续透传查询参数和统一错误码映射。前端工作台在统计区域展示查询范围、生成时间和数据截至时间，并沿用现有错误重试。

不引入快照表，不执行迁移，不改变城市字段缺失这一事实，不把实时聚合伪装成离线报表。

## 6. 错误与安全

- 参数错误统一返回 gRPC `InvalidArgument`，由 HTTP 层映射为 `40001`。
- 数据库错误继续原样进入系统错误处理，不返回空数据掩盖故障。
- 解析和范围校验在数据库查询前执行，避免无效请求占用连接。
- 统计接口保持只读，不写业务数据和审计日志。

## 7. 测试

覆盖：默认 30 天、单边时间补齐、90 天边界、超过 90 天、结束早于开始、未来时间、非法格式、城市筛选拒绝，以及六类响应生成时间字段存在且格式正确。保留既有 SQL mock 测试并更新请求参数期望值。

## 8. 验收

所有统计接口对非法范围在查询前稳定返回 `40001`；合法请求返回原有指标及 `generated_at/data_as_of`；前端能展示时间元数据；不产生数据库迁移和业务数据变更。
