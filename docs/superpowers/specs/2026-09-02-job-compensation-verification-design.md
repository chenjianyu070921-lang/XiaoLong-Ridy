# 任务补偿真实运行验证与保护设计

## 1. 目标

补齐 `job` 定时任务、退款补偿、派单补偿、管理后台审计 outbox 和通知补偿的可验证性，提供不污染业务数据的运行前检查和 dry-run 能力，并修正任务运行时自动修改数据库结构的问题。

## 2. 范围

### 2.1 包含

1. 增加 job 依赖预检脚本，检查配置完整性、MySQL、Redis、Kafka 和下游 RPC 连通性。
2. 增加只读任务摘要能力，输出退款队列、派单重试队列和审计 outbox 的积压数量、最早任务时间和失败状态数量。
3. 为补偿任务增加 dry-run 入口：只读取待处理记录和依赖状态，不发送 Kafka、不调用冻结/通知 RPC、不更新数据库或 Redis。
4. 为真实任务增加启动时执行一次的验证说明和日志边界，避免必须等待第一个定时周期才能发现配置问题。
5. 移除 `DailyReport` 运行时 `AutoMigrate`，改为依赖已存在的迁移表；表不存在时明确返回错误。
6. 补充 sqlmock、miniredis 和替身 RPC 测试，覆盖依赖缺失、空队列、积压摘要、dry-run 无副作用和重试耗尽状态。

### 2.2 不包含

- 不新增数据库表、字段、索引或迁移脚本。
- 不执行真实退款、派单、冻结、通知补偿。
- 不实现支付 HTTP 回调网关。
- 不引入监控平台、告警平台或新的消息队列消费者。

## 3. 设计方案

### 3.1 只读预检脚本

新增 `scripts/admin-test/job-preflight.ps1`，从显式参数或现有 job 配置读取目标地址。脚本只做：

- 校验 `job.yaml` 中 MySQL、Redis、Kafka、OrderRPC、DispatchRPC、DriverRPC、PushRPC 配置存在；
- 使用现有工具或最小 TCP 检查验证地址可解析；
- 输出需要人工执行的 Go dry-run 命令；
- 不打印配置中的密码、DSN 用户凭据或密钥。

脚本失败返回非零退出码，成功返回 0，适合 CI 或联调前置检查。

### 3.2 Dry-run 任务摘要

在 `job/internal/task` 增加只读摘要结构和方法，统一返回：任务名称、扫描数量、最早任务时间、失败数量、依赖状态和生成时间。Redis 队列只使用 `ZCARD`、`ZRANGE WITHSCORES` 等读操作；MySQL outbox 只执行 SELECT；不触发任何重试动作。

dry-run 入口通过独立 handler 方法或命令行参数调用，与生产定时循环隔离，默认不会启用，避免误把验证模式当成真实 worker。

### 3.3 任务启动行为

现有定时任务保持周期不变，但进程启动后先执行一次只读预检并记录结果。真实补偿任务是否立即执行由现有配置控制；本轮不改变重试间隔和业务动作，避免启动风暴。

### 3.4 日报表结构边界

`DailyReport` 任务不再调用 GORM `AutoMigrate`。任务直接写入既有 `daily_report` 表；如果表不存在或字段不匹配，返回明确错误，由部署迁移流程负责修复。这样不会在生产任务运行期间隐式改数据库结构。

## 4. 错误处理与安全

- 预检只报告连接失败和配置缺失，不尝试修复环境。
- dry-run 下游依赖不可用时返回依赖状态，不执行降级写入。
- 真实任务继续保留现有幂等、抢占、退避和最大重试次数。
- 任务日志只输出数量、任务类型和错误摘要，不输出密码、完整 DSN 或敏感业务载荷。
- 不修改用户、订单、支付、司机和位置业务数据。

## 5. 测试与验收

- 预检配置缺失、地址无效和成功路径。
- dry-run 空队列、存在积压、存在 failed 记录和 Redis 读取错误。
- dry-run 前后数据库/Redis mock 无写操作期望。
- DailyReport 在表存在时写入，在表不存在时返回错误且不执行建表。
- `go test ./job/...` 通过。
- 预检脚本在脱敏配置下返回明确退出码；真实远程环境验证需由部署人员在授权环境执行。

## 6. 验收边界

本轮完成“代码可验证、运行前可检查、失败可定位”的能力，不宣称已经完成生产环境联调。真实环境仍需在具备 MySQL、Redis、Kafka 和 RPC 服务的授权环境中执行脚本和 dry-run，并由运维确认任务日志与积压指标。
