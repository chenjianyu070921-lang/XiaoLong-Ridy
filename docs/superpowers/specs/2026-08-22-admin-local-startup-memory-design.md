# 管理后台本地启动内存优化设计

## 目标

在不改变管理后台接口、业务逻辑、数据库结构或业务数据的前提下，降低本地开发启动时的内存占用，使管理后台前端能够稳定访问。

验收标准：

- `web/admin`、`api/admin`、`rpc/adminsvc` 三个进程可持续运行。
- 浏览器可访问 `http://127.0.0.1:5173` 并显示管理后台登录页。
- 仅保留上述三个必要进程，不启动订单、司机、价格等下游服务。
- 启动后采集三个进程的内存占用，确认不存在持续增长。

## 范围与边界

本轮只优化本地开发启动路径：Vue/Vite 前端、管理 HTTP API 与管理 RPC 服务。

不修改数据库表、索引、迁移脚本或任何业务数据；不调整 HTTP、RPC 出入参；不修改订单、司机、价格等下游服务。管理 RPC 对下游服务继续使用既有非阻塞客户端配置，因此仅在页面实际调用相关功能时才暴露下游不可用错误。

## 方案

### 前端

为 Vite 开发服务提供受控的 Node 堆上限，避免 Node 在系统虚拟内存紧张时无限申请堆空间。沿用已安装依赖与现有 `5173` 端口、`/admin` 代理规则，不增加新的前端依赖或运行时服务。

### 管理 API 与 RPC

为本地启动命令提供 Go 运行时内存回收参数，减少空闲堆保留；不修改现有连接池、鉴权、中间件或业务查询逻辑。RPC 下游客户端继续使用非阻塞连接，避免因未启动的下游服务阻塞管理后台的基础启动。

### 启动编排

新增或完善本地开发启动入口，仅启动以下进程：

1. `rpc/adminsvc`
2. `api/admin`
3. `web/admin`

启动脚本应写入本地日志，启动前检查端口占用，启动后检查 `8084`、`8717` 与 `5173` 的监听状态。出现依赖缺失、端口冲突或进程退出时，应输出明确错误，不自动启动额外服务。

## 验证

1. 在不启动下游 RPC 服务的环境中执行本地启动入口。
2. 检查三个目标端口均处于监听状态。
3. 请求前端首页，确认返回页面内容。
4. 记录 Node、管理 API 与管理 RPC 进程的工作集内存，并在短时间观察中确认未持续增长。
5. 确认未产生数据库迁移、写入或结构变更。

## 风险与处理

Node 堆上限设置过低可能导致依赖预构建或大型页面编译失败，因此以稳定启动为优先，在实际启动验证后保留足够余量。下游服务未运行时，订单、司机或价格等依赖下游的页面可能返回现有的服务不可用错误；这属于本地最小服务集的预期边界，不通过伪造数据或改变业务接口规避。
