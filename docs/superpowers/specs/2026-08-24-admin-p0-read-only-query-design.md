# 管理后台 P0 只读查询能力设计

## 目标

为管理后台补齐三项高频只读能力：用户订单历史、用户优惠券历史和司机列表。实现必须遵循数据归属与调用边界：`api/admin -> adminsvc -> 数据归属 RPC 服务`，不由管理服务直连订单、用户券或司机业务表。

本批仅新增查询与展示能力，不包含司机冻结、订单轨迹、人工改派、退款及任何数据库结构或业务数据变更。

## 方案选择

采用归属服务提供只读 RPC、`adminsvc` 统一鉴权和响应适配的方案。

不采用 `adminsvc` 直接访问其他服务数据表的快速方案，避免破坏微服务数据边界。也不允许前端绕过 `api/admin` 或 `adminsvc` 直接调用业务 RPC。

## 接口设计

新增下列后台 HTTP 接口，均沿用统一响应格式与 `page/list/total/page_size` 分页结构：

| 接口 | 查询参数 | 数据归属服务 | 用途 |
| --- | --- | --- | --- |
| `GET /admin/v1/users/{id}/orders` | `status`、`page`、`page_size` | `ordersvc` | 查询指定用户的订单历史 |
| `GET /admin/v1/users/{id}/coupons` | `status`、`page`、`page_size` | `usersvc` | 查询指定用户的领券、用券、过期和锁定记录 |
| `GET /admin/v1/drivers` | `keyword`、`status`、`page`、`page_size` | `driversvc` | 查询司机基础资料、账号状态、在线状态与审核摘要 |

`status=0` 表示不过滤。页码小于 1 归一化为 1；每页数量默认 20，最大 100。

## 服务契约与数据流

1. `api/admin` 复用既有认证中间件，解析路径 ID 和查询参数，并把验证后的会话 token 透传给 `adminsvc`。
2. `adminsvc` 复用服务端会话验证与 RBAC；通过 `ordersvc` 查询用户订单、通过 `usersvc` 查询用户券、通过 `driversvc` 查询司机列表，并映射为管理端响应模型。
3. `ordersvc` 增加面向后台的用户订单历史只读 RPC。它按 `user_id`、订单状态和分页查询，返回订单摘要及总数。
4. `usersvc` 增加面向后台的用户优惠券历史分页 RPC。现有乘客端 `ListMyCoupons` 不满足后台分页契约，因此不复用该接口。
5. `driversvc` 将已有列表仓储与列表逻辑补充到正式 proto 服务契约中，生成稳定的 RPC 客户端桩代码。

## 数据最小化与安全

司机内部模型包含密码哈希、身份证号和驾驶证号。新的管理端司机列表响应只能包含：司机 ID、手机号、真实姓名、头像、账号状态、在线状态、创建时间、更新时间及必要审核摘要；不得包含密码哈希、身份证号、驾驶证号、保险信息或其他非必要敏感信息。

用户订单和用户券查询仅限后台已授权管理员。所有新增接口均为只读，不写入 `admin_operation_log`，也不修改用户、司机、订单、优惠券或关联表。

## 前端设计

用户详情页增加“订单历史”和“优惠券历史”只读页签，使用分页表格展示并按状态筛选。新增司机列表菜单、路由、请求封装和列表页面，支持关键字、账号状态和分页筛选；司机详情仅展示后端允许返回的安全字段。

前端请求继续通过现有 `/admin/v1` 请求封装，沿用统一的登录失效、无权限和业务错误提示，不持久化或展示任何服务端敏感字段。

## 错误处理

- 非法路径 ID、状态或分页参数返回 `40001`。
- 用户或司机不存在返回 `40401`。
- 登录态缺失或失效返回 `40004`；无权限返回 `40003`。
- 下游 RPC 不可用时返回明确的服务不可用错误，不以空列表掩盖故障。
- 空结果返回正常的空分页响应。

## 验收与测试

1. 覆盖三个 RPC 的参数归一化、状态筛选、分页、空结果和下游仓储错误测试。
2. 覆盖 `adminsvc` 的权限校验、响应映射与下游错误传播测试。
3. 覆盖 `api/admin` 的路由、非法参数、未登录、无权限和统一响应结构测试。
4. 覆盖司机响应不包含密码哈希、身份证号、驾驶证号等敏感字段的断言。
5. 前端执行 `npm run build`，并联调用户详情双页签和司机列表的筛选、分页、错误状态。

## 非目标

本设计不修改数据库迁移脚本、不补录测试业务数据、不加入司机冻结或解冻、不新增订单轨迹、人工改派、退款或统计能力。这些内容按既定优先级在后续独立设计和实施。
