# 管理后台地图轨迹与运力调度大屏设计

## 1. 目标

在不修改数据库结构、不改变司机和位置服务权威边界的前提下，补齐管理后台的地图轨迹查看和基础实时运力监控能力。复用现有 `adminsvc`、`driversvc`、`locationsvc` 接口，真实展示可查询到的位置数据；无法取得位置时明确降级，不生成模拟坐标。

## 2. 范围

### 2.1 包含

1. 订单详情页将已有轨迹点绘制为地图折线，展示起点、终点、轨迹点信息，并提供按点回放。
2. 新增后台运力地图查询接口，聚合司机列表和司机最新位置。
3. 新增运力地图页面，展示司机位置、在线状态、行程状态、速度和最后上报时间。
4. 运力页面每 15 秒轮询一次，支持手动刷新和按状态筛选。
5. 单次最多返回 200 名司机；单个司机位置查询失败只跳过该点并保留失败计数。
6. 增加 RPC、HTTP、前端数据转换和降级测试。

### 2.2 不包含

- 不新增 WebSocket、SSE 或消息推送链路。
- 不修改 `locationsvc`、`driversvc` 的数据库模型、表结构和位置写入逻辑。
- 不实现自动派单、司机调度决策或改派操作。
- 不伪造没有上报的位置和轨迹点。

## 3. 数据流与接口

### 3.1 运力快照

`GET /admin/v1/capacity/map` -> `adminsvc.GetCapacityMap` -> `driversvc.ListDrivers` + `locationsvc.GetDriverLocation`。

请求参数：`status`（可选，司机状态筛选）、`online_status`（可选，0/1/2）、`limit`（默认 100，最大 200）。

响应字段：`generated_at`、`drivers[]`、`total`、`available_count`、`in_trip_count`、`offline_count`、`position_failure_count`。司机项包含 `driver_id`、`driver_status`、`online_status`、`lng`、`lat`、`heading`、`speed_kmh`、`report_time`。

司机列表查询失败时整体返回错误；单个位置查询失败只计数并跳过地图点，避免少数脏数据导致大屏白屏。

### 3.2 订单轨迹

继续调用现有 `GET /admin/v1/orders/{id}/track`，不改变请求和响应契约。前端将 `points[].lng/lat` 转换成地图 SDK 所需坐标，按 `recorded_at` 升序绘制折线；第一点和最后一点分别作为起点、终点。轨迹点为空或坐标非法时显示空状态。

## 4. 后端实现

在 `rpc/adminsvc/admin.proto` 增加运力地图请求、司机位置项和响应消息及 RPC。`adminsvc` 只负责参数校验、跨服务聚合和字段适配，不直接读取司机或位置表。位置查询使用固定并发上限，避免司机数量增加时创建无限 goroutine；返回结果按司机 ID 稳定排序。

HTTP 网关新增独立 handler 和路由，沿用现有后台鉴权、错误码和响应包装。非法 `limit` 返回 `40001`，超过上限按 200 截断或直接返回参数错误，以现有分页约定为准。

## 5. 前端实现

新增 `web/admin/src/views/capacity/index.vue`，复用后台布局和请求封装。地图优先使用项目已配置的高德 Key；若 SDK 加载失败，显示司机列表和错误提示，不阻断状态统计。页面提供状态筛选、刷新按钮、自动刷新开关和最后更新时间。

订单详情页增加地图区域和回放按钮。回放仅在本地按轨迹点时间顺序移动标记，不产生任何后端写操作；切换订单或关闭区域时清理定时器和地图实例。

## 6. 错误处理与安全

- 所有聚合接口保持只读，不写业务表和审计表。
- 下游服务不可用时返回统一错误；单点位置失败采用部分成功并返回失败计数。
- 强制限制返回数量和刷新频率，避免大范围查询压垮 RPC 和浏览器。
- 坐标必须是有限数值且经纬度在合法范围内，非法点直接丢弃并计入失败数。

## 7. 测试与验收

- `adminsvc`：司机列表为空、位置成功、位置失败降级、数量上限、非法参数、稳定排序。
- `api/admin`：新路由注册、鉴权和错误码映射。
- 前端：轨迹点转换、空轨迹、无效坐标、地图 SDK 失败降级和轮询清理。
- 后端执行 `go test ./rpc/adminsvc/... ./api/admin/...`；前端执行可用的 Vite 构建或静态检查。

验收标准：订单详情可在真实轨迹数据存在时绘制并回放；运力页面可展示真实司机位置和状态，位置服务部分失败时页面仍可用；无数据库迁移和业务数据写入。
