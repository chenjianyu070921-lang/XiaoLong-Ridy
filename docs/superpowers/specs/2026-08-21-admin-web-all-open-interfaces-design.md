# 管理后台前端全开放接口设计

## 1. 背景与范围

`web-admin` 是管理后台独立前端工程，使用 Vue 3、Vite、Element Plus、Pinia、Axios 和 Hash 路由。原型图仅作为视觉层级参考，页面字段、请求参数、状态和操作能力以当前 `api/admin` 路由、`api/admin/internal/types` 类型定义及管理后台接口文档为准。

本次覆盖当前已注册的后台能力：登录与会话、用户、司机资质审核、订单与异常订单、优惠券及发券任务、计价规则、营销活动、投诉/申诉工单、运营统计、导出任务、风控黑名单与命中记录、操作日志。司机基础列表、司机冻结、订单轨迹、改派、退款、用户券列表等未开放路由不进入前端导航和交互。

本次只修改 `web-admin` 和本设计文档，不修改 Go 服务、RPC、数据库结构、迁移脚本或业务数据。

## 2. 信息架构

左侧导航按业务域组织：

- 工作台：统计总览、订单统计、优惠券统计。
- 用户管理：用户列表、用户详情、冻结/解冻。
- 司机资质审核：审核列表、审核详情、通过/驳回。
- 订单管理：订单列表、异常订单、订单详情、后台取消。
- 营销中心：优惠券模板、发券任务、计价规则、活动配置。
- 工单中心：投诉/申诉工单列表、详情、创建、状态动作、证据操作。
- 数据中心：导出任务。
- 风控管理：黑名单、风控命中记录。
- 审计管理：操作日志。

导航优先使用 `GET /admin/v1/menus` 的返回结果和 `perm` 字段；接口失败或返回空菜单时使用仅包含已开放路由的静态兜底菜单。未匹配前端路由的后端菜单项不渲染。

## 3. 页面与接口

### 3.1 登录与布局

- `POST /admin/v1/auth/login`：仅提交 `username`、`password`。
- `POST /admin/v1/auth/logout`：退出时提交空对象并清理本地会话。
- `GET /admin/v1/auth/me`：刷新后校验管理员信息。
- `GET /admin/v1/menus`：加载角色菜单与权限。

布局包含侧栏、顶栏、面包屑、角色信息、退出按钮和主内容区。保留原型的深色高密度运营风格，但所有展示内容来自接口。

### 3.2 用户管理

列表调用 `GET /admin/v1/users`，支持 `keyword`、`status`、`start_time`、`end_time`、`page`、`page_size`。详情调用 `GET /admin/v1/users/{id}`，展示用户接口返回的手机号、昵称、实名、证件号、注册来源、性别、状态和时间字段。冻结/解冻分别调用对应 POST 接口，只提交 `reason`、`remark`。

### 3.3 司机资质审核

列表调用 `GET /admin/v1/driver-certifications`，支持 `keyword`、`audit_status`、时间范围和分页。详情展示司机、车辆、证照 URL、审核状态与审核记录。通过和驳回分别调用 `/approve`、`/reject`，请求体仅包含 `remark`。只有待审核状态显示写操作按钮。

### 3.4 订单管理

订单列表调用 `GET /admin/v1/orders`，支持订单号、状态、用户 ID、司机 ID、下单时间和分页；异常订单调用 `GET /admin/v1/orders/abnormal`，`abnormal_type` 仅允许 `cancel`、`payment`、`dispatch` 或空值。详情调用 `GET /admin/v1/orders/{id}`，分区展示订单、状态日志、派单记录、价格、支付和结算；关联对象为空时显示空态。后台取消调用 `/cancel`，请求体只包含 `reason`，成功后重新获取详情。

### 3.5 营销中心

优惠券模板调用列表、新增、编辑、停用接口。金额字段作为字符串处理，不使用浮点运算；编辑页提示已发放优惠券不应修改核心规则。发券调用 `/issue`，当前页面使用显式用户 ID 输入，序列化为 `target_config` JSON 字符串；发券任务调用 `GET /coupon-issue-tasks`，展示任务编号、成功/失败数量和失败原因。

计价规则页面覆盖列表、详情、新增、编辑、启用和停用，表单严格对应真实 `PriceRuleSaveRequest` 字段。活动页面覆盖列表、新增、编辑、发布和回滚；`config`、`target_config` 先做 JSON 合法性校验，再作为字符串提交。

### 3.6 工单中心

工单页面覆盖当前已注册 `/admin/v1/work-orders` 及其详情/动作/证据相关路由。创建、状态流转和证据操作分别使用当前 Go 类型定义中的 `WorkOrderRequest`、`WorkOrderActionRequest`、`WorkOrderEvidenceRequest` 字段。页面不自行推导状态机之外的动作；后端返回的动作失败以状态冲突提示并重新拉取详情。

### 3.7 统计、导出、风控和日志

统计页面并发读取 `statistics/overview`、`statistics/orders`、`statistics/coupons`。城市筛选不提供默认值，非空 `city_code` 仅在接口明确支持时提交；订单统计时间范围按订单创建时间查询。

导出页面创建、列表和详情均使用导出任务接口。前端只提交后端当前接受的 `export_type` 与白名单 `filters`，不假设本地文件可直接下载；任务状态由详情/列表刷新获得。

黑名单页面支持列表、新增和解除；新增只提交 `target_type`、`target_id`、`reason`，解除提交可选 `reason`。命中记录与操作日志均为只读分页列表。

## 4. 工程结构

```text
web-admin/src/
├── api/               # 按业务域封装真实 HTTP 接口
├── components/        # 分页、状态、日期、JSON、确认等共享组件
├── layout/            # 后台整体布局
├── router/            # Hash 路由与登录守卫
├── store/             # Pinia 登录态与权限
├── utils/             # 枚举、格式化与请求参数工具
└── views/             # 各业务域页面
```

页面只调用 `src/api`，不直接拼接 URL 或访问存储层。共享组件统一处理加载、空数据、错误重试、分页、日期范围、状态标签、金额显示和操作确认。新增源码补充中文注释，说明模块、数据结构、函数入参返回值和关键接口约束。

## 5. 权限、错误与一致性

- 写按钮根据 `/menus` 返回的 `perm` 隐藏；后端 403 仍必须显示无权限提示。
- 401/`40004` 清理 token 并回到登录页；40001、40401、40901、40902、50000 分别给出参数、资源、状态、幂等和系统错误提示。
- 写操作统一使用确认弹窗，提交中禁用按钮；成功后重新请求列表或详情，不做乐观更新。
- 详情关联数据允许为空，主对象优先呈现；网络失败提供局部重试。
- 前端不修改数据库，不执行迁移，不把原型虚构字段发送给后端。

## 6. 验收标准

1. `npm run build` 成功。
2. 未登录访问受保护路由会回到登录页，登录后能加载菜单和管理员信息。
3. 所有已开放接口均有页面、筛选、详情或对应操作入口；未开放接口无导航入口。
4. 所有列表具备真实接口分页、空态、加载态、错误重试和刷新。
5. 所有请求体与当前 `api/admin/internal/types` 定义一致，金额和 JSON 字符串不发生精度或类型转换错误。
6. 写操作覆盖成功、失败、重复提交和状态冲突场景。
7. 导出任务、工单详情、订单关联区块能正确处理异步状态和空数据。
