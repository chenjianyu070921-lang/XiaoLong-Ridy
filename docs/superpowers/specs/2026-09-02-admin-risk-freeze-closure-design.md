# 管理后台风控命中冻结处罚闭环设计

## 1. 目标与范围

本期在现有管理后台风控命中处置接口上增加 `freeze` 动作，完成“风控命中记录 -> 用户/司机冻结 -> 操作审计 -> 可追踪结果”的闭环。

本期只复用现有 `usersvc` 和 `driversvc` 冻结 RPC，不新增 `punishsvc`，不新增数据库表，不修改现有数据库结构，不改变用户端、司机端接口。

支持对象类型：`user`、`driver`。`device`、`phone` 命中记录不支持直接冻结，返回逐条失败原因，运营人员仍可选择转工单或加入黑名单。

## 2. 现有边界

HTTP 入口保持不变：

```text
POST /admin/v1/risk/hit-records/actions
```

后台 API 只负责会话校验、请求解析和响应包装；`adminsvc` 负责风控命中查询、动作编排、审计和逐条结果；用户冻结由 `usersvc` 权威服务执行，司机冻结由 `driversvc` 权威服务执行。

## 3. 接口契约

请求新增动作约定：

```json
{
  "ids": [10001, 10002],
  "action": "freeze",
  "reason": "高风险登录行为"
}
```

沿用现有字段：`ids` 支持单条或批量，`reason` 必填，`admin_id` 和 `ip` 从已认证管理员会话及请求上下文生成，不信任客户端伪造值。

响应沿用 `RiskHitActionResponse`：

- `success_count`：冻结 RPC 和审计均成功的命中记录数；
- `fail_count`：未完成闭环的命中记录数；
- `failure_reasons`：按命中记录 ID 返回失败原因；
- `work_order_ids`：本动作为空，保留现有兼容字段。

## 4. 处理流程

每个命中 ID 独立处理，批量请求部分成功不回滚其他记录：

1. 去重并过滤非正数 ID，校验动作和原因。
2. 查询命中记录，确认记录存在且目标 ID 为正数。
3. 检查该命中记录是否已经完成冻结处置，已完成时返回幂等冲突。
4. 按 `target_type` 调用冻结 RPC：
   - `user`：调用 `UsersSvc.FreezeUser`；
   - `driver`：调用 `DriversSvc.FreezeDriver`，同时由司机域同步离线状态；
   - 其他类型：返回“目标类型不支持冻结”。
5. 冻结 RPC 成功后写入 `admin_operation_log`，模块为 `risk`，动作建议为 `freeze`，目标类型为 `risk_hit_record`，详情包含命中场景、目标类型/ID、命中原因和处置说明。
6. 审计写入失败时写入既有 `admin_audit_outbox`，本条返回失败，不把失败误报为成功；补偿任务后续重试审计写入。
7. 列表接口基于现有命中记录、黑名单、工单和操作日志推导 `handle_status`，冻结成功记录显示 `frozen`，`handle_action` 为 `hit_freeze`，并返回处理管理员和时间。

## 5. 幂等与一致性

- 同一命中记录只允许一次成功冻结处置；重复请求返回冲突，不重复调用冻结 RPC。
- 冻结 RPC 成功但审计主表写入失败时，必须创建 outbox 补偿记录；若主表和 outbox 均失败，返回系统错误并保留失败日志。
- 不在 adminsvc 直接更新用户表或司机表，不执行跨服务数据库事务。
- 不自动将冻结动作转换为黑名单或工单，三类动作保持语义独立。
- 冻结 RPC 的超时和下游不可用必须返回明确失败原因，不能返回假成功。

## 6. 权限

冻结属于高危风控动作，沿用后台 RBAC，至少要求超级管理员或已有风控处置权限；普通运营角色不得执行 `freeze`。服务端再次校验权限，不能只依赖前端隐藏按钮。

## 7. 前端交互

风控命中列表新增“冻结对象”操作，仅当目标类型为用户/司机且状态为 `pending` 时展示。提交前要求填写原因；批量冻结后展示成功数、失败数和失败原因，并刷新列表。设备/手机号命中不展示冻结按钮。

## 8. 测试设计

后端单元测试覆盖：

- 用户命中调用 `FreezeUser` 并记录成功；
- 司机命中调用 `FreezeDriver` 并记录成功；
- 不支持的目标类型失败；
- 冻结 RPC 失败不写成功审计；
- 审计主表失败时创建 outbox 且返回失败；
- 重复冻结返回幂等冲突；
- 批量请求部分成功时统计和失败原因正确；
- 普通角色无权执行冻结。

API 路由测试覆盖：动作透传、原因校验、统一错误码和批量响应。

## 9. 非目标

- 不新增数据库迁移和处罚服务；
- 不实现自动风控冻结；
- 不修改支付、统计、地图和订单状态机；
- 不改变现有 `review_pass`、`add_blacklist`、`create_work_order` 的请求语义。

## 10. 验收标准

管理员可从风控命中页面对用户或司机执行冻结；冻结成功后对应域状态真实变更，司机同时离线；后台返回可核对的成功/失败结果，操作日志可查询，审计失败进入补偿队列；重复提交不会重复执行；设备和手机号命中不会被错误冻结。
