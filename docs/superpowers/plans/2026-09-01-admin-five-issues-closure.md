# 管理后台五项问题实施计划

## 目标

在保持现有 HTTP/RPC 契约和数据库不变的前提下，完成业务路由独立页面、复杂表单、订单详情关联信息、统计图表和后端路由拆分。

## 实施步骤

### 1. 建立后端路由行为基线

- 阅读 `api/admin/internal/handler/router.go` 的所有注册分支和 `router_test.go` 的全量冒烟用例。
- 按认证/管理员、用户、司机、订单、营销、统计风控、导出工单域新增注册文件。
- 保持 `NewRouter` 的根路径、中间件、处理函数、HTTP 方法和路径参数不变。
- 运行 `go test ./api/admin/...`，失败时先修复拆分造成的编译或注册遗漏。

### 2. 调整前端路由与业务页面入口

- 对照 `web/admin/src/api/modules.js` 和接口文档，列出当前所有菜单到组件的映射。
- 将用户、司机认证、订单、工单等已有页面接入对应路由；为优惠券、计价规则、营销、风控、日志、导出等已有接口创建最小独立页面。
- 抽取列表页共用的加载、分页、空状态和错误状态逻辑，避免复制请求实现。
- 保留布局、登录鉴权和权限码行为，确保刷新和深链接可用。

### 3. 完善复杂表单

- 扩展 `BusinessFormDialog.vue` 的字段类型和校验配置。
- 优惠券表单覆盖类型、面额/折扣、门槛、有效期、总量和限领字段。
- 计价规则表单覆盖起步价、里程费、时长费等接口定义字段。
- 营销活动表单覆盖活动类型、配置 JSON、发布范围和状态动作。
- 提交时锁定按钮、显示后端错误，成功后刷新列表；不改变请求体字段名。

### 4. 补齐订单详情关联区域

- 在 `web/admin/src/views/order/detail.vue` 中保留订单主信息和既有操作。
- 订单主详情成功后并行请求用户订单历史和用户优惠券接口。
- 增加独立加载、空数据、错误重试状态，关联请求失败不得影响主详情。
- 按 API 文档字段渲染状态、金额、时间和券信息，避免从前端推导业务状态。

### 5. 接入统计图表

- 从 `modules.js` 复用 overview、orders、drivers、revenue、coupons 请求。
- 在 `console/index.vue` 或拆出的总览组件中增加指标卡和四组图表模型转换。
- 优先使用已有依赖；若无图表依赖，使用本地轻量 SVG/Canvas 组件，不引入大型运行时。
- 实现并发请求、局部失败、空数据和重试状态。

### 6. 测试与验证

- 为路由拆分保留并补充 HTTP 方法/路径映射测试。
- 为订单详情和统计数据转换增加可测试的纯函数或组件测试边界。
- 执行 `go test ./api/admin/... ./rpc/adminsvc/...`。
- 执行 `npm run build`（工作目录 `web/admin`）。
- 使用现有后台启动脚本做登录、列表、订单详情和统计页面冒烟检查；不执行迁移脚本。

## 文件边界

允许修改：`api/admin/internal/handler`、`web/admin/src/router`、`web/admin/src/views`、`web/admin/src/components`、必要的 `web/admin/src/api`、对应测试和本计划/设计文档。

禁止修改：数据库迁移脚本、无关服务、已存在但与本五项问题无关的用户改动；禁止回退工作区已有变更。

## 完成判定

五项问题均可通过页面行为或路由测试验证；后端测试和前端构建通过；对外接口、权限、数据库结构和业务数据无变化。
