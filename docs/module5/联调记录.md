## 二、链路图

```
CreatePayment（支付预下单）
  → 生成 payment_no，创建 payment 单（status=1 待支付）
  → 调 MockChannel 下单，回填 transaction_id + pay_params
NotifyPayment（模拟支付宝回调）
  → 验签（本地 keys 为空时降级 MockVerifier）
  → payment.status 1 → 2（支付成功），回填流水号 + 支付时间
  → 发 Kafka 事件 order.paid（失败仅记日志，不阻断）
  → 调 ordersvc.GetOrder 拿 driver_id
  → 触发 SettleOrder 生成 settlement 结算单
GetPayment（支付查询）
  → 按 payment_no 返回支付状态（status=2）
RefundPayment（退款）
  → 校验可退金额 → MockChannel 退款 → 回写 refund_amount
```

## 四、真实联调步骤

### 前置条件

1. 启动 MySQL 并执行建表 + seed：

```powershell
docker compose -f deploy/docker/infra.yml up -d mysql
# 建表：scripts/sql/migrate/05_trade_module.sql
# seed：scripts/sql/migrate/07_price_rule_seed.sql
```

2. 对齐 mysql 账号密码：
   - `rpc/paysvc/etc/paysvc.yaml` 默认 `root:root123`
   - `deploy/docker/infra.yml` 的 MySQL root 密码默认 `root`
   - **二选一改一致**（改 yaml 或改 compose 环境变量）

### 一键联调

```powershell
powershell -ExecutionPolicy Bypass -File scripts/e2e/run_pay_e2e.ps1
```

脚本自动：启动 paysvc → 跑 `pay_e2e_client.go`（直连 50054 跑全链路）→ 停止 paysvc。

### 手动联调（可选）

```bash
# 终端1：启动 paysvc
go run rpc/paysvc/paysvc.go -f rpc/paysvc/etc/paysvc.yaml

# 终端2：跑联调客户端
go run scripts/e2e/pay_e2e_client.go -target 127.0.0.1:50054 -order 1001 -amount 2500 -refund 1000
```

预期输出依次打印：payment_no / transaction_id / 回调 success / 查询 status=2 / 结算抽成 500 + 司机实收 2000 / 退款 refunded=1000。

## 七、支付渠道配置说明（2026-08-28 补充）

> 组长 P0 ②：CreatePayment 真实渠道硬校验（M5-12）。

### 配置方式（二选一）

1. **paysvc.yaml** 直接填（仅 dev 沙箱建议）：
```yaml
alipay:
  appId: "9021000161684648"
  privateKey: "..."
  alipayPublicKey: "..."
  notifyUrl: "http://<域名>/api/pay/callback/alipay"
  sandbox: true   # 沙箱环境
```

2. **环境变量注入**（生产推荐，敏感信息不落库）：
```bash
ALIPAY_APP_ID=
ALIPAY_PRIVATE_KEY=
ALIPAY_PUBLIC_KEY=
ALIPAY_NOTIFY_URL=
ALIPAY_GATEWAY=
```

### mode 语义（M5-12 硬校验）

| mode | 缺密钥时渠道行为 | 说明 |
| --- | --- | --- |
| 生产（mode 空） | **paysvc 启动失败** | 绝不 mock，杜绝"假装上线"假流水 |
| test / dev | 降级 MockChannel | 本地联调无沙箱密钥可跑通流程 |

沙箱密钥申请：支付宝开放平台 → 沙箱环境 → 应用公钥/私钥生成后填入。

### 回调路由（P0 ①）

- **主路径（生产）**：`POST /api/pay/callback/alipay` 挂在 **api/admin 网关**（:8888），内部 zrpc 透传 `paysvc.NotifyPayment`。
- **应急回退（dev）**：paysvc 进程自带 `httpAddr: 8888` 直连路径保留，仅本地快速联调。

### 对账/分账（P0 ③）

新增表：`payment_reconcile_diff`、`payment_channel_reconcile_log`（`scripts/sql/migrate/08_pay_reconcile.sql`）。
- 对账 job：扫描已支付单，拉取渠道快照比对差异，写差异表 + 执行日志。
- 自动结算 job：扫描已支付未结算单，经 `OrderClient.GetDriverId` 拿真实司机，生成结算单并打 `auto_settled=1`。
- 渠道对账接口（alipay.trade.query）为真实对接点，已留 `QueryChannelTransactions` 函数占位。
