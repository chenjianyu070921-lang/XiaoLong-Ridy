## 二、链路图

```
CreatePayment（支付预下单）
  → 生成 payment_no，创建 payment 单（status=1 待支付）
  → 调 MockChannel 下单，回填 transaction_id + pay_params
NotifyPayment（模拟支付宝回调）
  → 验签（本地 keys 为空时降级 MockVerifier）
  → payment.status 1 → 2（支付成功），回填流水号 + 支付时间
  → 发 Kafka 事件 order.paid（失败仅记日志，不阻断）
  → 调 ordersvc.GetOrder 拿 driver_id
  → 触发 SettleOrder 生成 settlement 结算单
GetPayment（支付查询）
  → 按 payment_no 返回支付状态（status=2）
RefundPayment（退款）
  → 校验可退金额 → MockChannel 退款 → 回写 refund_amount
```

## 四、真实联调步骤

### 前置条件

1. 启动 MySQL 并执行建表 + seed：

```powershell
docker compose -f deploy/docker/infra.yml up -d mysql
# 建表：scripts/sql/migrate/05_trade_module.sql
# seed：scripts/sql/migrate/07_price_rule_seed.sql
```

2. 对齐 mysql 账号密码：
   - `rpc/paysvc/etc/paysvc.yaml` 默认 `root:root123`
   - `deploy/docker/infra.yml` 的 MySQL root 密码默认 `root`
   - **二选一改一致**（改 yaml 或改 compose 环境变量）

### 一键联调

```powershell
powershell -ExecutionPolicy Bypass -File scripts/e2e/run_pay_e2e.ps1
```

脚本自动：启动 paysvc → 跑 `pay_e2e_client.go`（直连 50054 跑全链路）→ 停止 paysvc。

### 手动联调（可选）

```bash
# 终端1：启动 paysvc
go run rpc/paysvc/paysvc.go -f rpc/paysvc/etc/paysvc.yaml

# 终端2：跑联调客户端
go run scripts/e2e/pay_e2e_client.go -target 127.0.0.1:50054 -order 1001 -amount 2500 -refund 1000
```

预期输出依次打印：payment_no / transaction_id / 回调 success / 查询 status=2 / 结算抽成 500 + 司机实收 2000 / 退款 refunded=1000。

## 2026-08-20 order.paid 订单闭环联调记录

### 范围

- 成员 5：`paysvc.NotifyPayment` 支付成功后发布 `order.paid`。
- 成员 4：`mq-consumer/order-event-consumer` 消费 `order.paid` 并调用 `ordersvc.ConfirmPaid`。
- 乘客端：订单详情 `GetOrder`、订单列表 `ListOrders` 继续读取 ordersvc 最新状态。

### 链路结果

1. `order.paid` 事件字段按 `{order_id,payment_no,amount_cents,paid_at}` 解析。
2. `order-event-consumer` 新增 `OrderRPC` 客户端，收到 `order.paid` 后调用 `ConfirmPaid`。
3. `ConfirmPaid` 将订单从 `WAIT_PAY(4)` 更新为 `COMPLETED(5)`，写入状态日志，并发布 `order.status.changed`。
4. `ConfirmPaid` 成功后按真实 `order_id` 核销 `user_coupon`：`status=2`、`order_id=订单ID`、`used_at=当前时间`、`locked_order_id=0`。
5. 乘客端详情/列表无需额外改接口，调用现有 `GetOrder/ListOrders` 可刷新到 `status=5`。

### 验证记录

- 已通过：`go test ./api/passenger/internal/logic`。
- 未完整通过：相关多包测试受仓库既有测试替身接口漂移影响阻塞：`usersvc` 测试缺少新增实名认证参数，`ordersvc` 旧 fake 缺少 `SaveActualOrderPrice/GetPayment` 方法。该阻塞与本次支付闭环代码路径无关。

### 评价接口

接口：

```http
POST /api/passenger/v1/reviews/submit
Authorization: Bearer <token>
Content-Type: application/json

{"orderId":123,"rating":5,"comment":"服务很好","tags":"准时,礼貌"}
```

规则：

- 仅允许订单所属乘客评价自己的订单。
- 仅允许已完成订单评价，且订单必须已分配司机。
- `rating` 取值为 1 到 5。
- `order_review.order_id` 唯一，重复评价返回业务码 `41031`。
- grpc 模式下配置 `PASSENGER_MYSQL_DSN` 后写入 MySQL；local/test 模式使用内存仓储。
