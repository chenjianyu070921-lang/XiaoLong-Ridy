## 1. 服务概览

| 服务 | 目录 | 监听端口 | 职责 |
| --- | --- | --- | --- |
| pricesvc | `rpc/pricesvc` | 50053 | 计价规则、行程价格预估、优惠券抵扣、高峰溢价 |
| paysvc | `rpc/paysvc` | 50054 | 支付预下单、回调、查询、退款、司机结算 |

- 通信方式：gRPC（go-zero zrpc）
- 金额单位：**接口与计算统一使用「分」(int64)**，避免浮点误差；数据库存储 `decimal(10,2)` 元。

| `order_price` | 订单价格明细（预估/实付快照） |
| `payment` | 支付单 |
| `settlement` | 订单结算（司机收入/平台抽成） |

## 3. pricesvc 接口

### 3.1 EstimatePrice — 行程价格预估

根据计价规则 + 里程/时长估算费用，返回各分项费用与总价（分）。

**请求 `EstimatePriceRequest`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| user_id | int64 | 用户ID |
| city_code | string | 城市编码，如 `110000` |
| car_type | int32 | 车型：1特惠快车 2快车 3拼车 |
| distance_m | int64 | 预估里程（米） |
| duration_s | int64 | 预估时长（秒） |
| timestamp | int64 | 预估时刻（Unix 秒），用于判断夜间；0 表示当前时间 |

**响应 `EstimatePriceResponse`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| price_rule_id | int64 | 命中的计价规则ID |
| detail | PriceDetail | 费用明细 |
| total_cents | int64 | 预估总价（分） |

**`PriceDetail` 明细**

| 字段 | 说明 |
| --- | --- |
| base_fee_cents | 起步价 |
| distance_fee_cents | 里程费 |
| time_fee_cents | 时长费 |
| night_fee_cents | 夜间附加费 |
| dynamic_fee_cents | 动态调价费 |
| total_cents | 合计 |

**计价公式**

```
里程费 = max(0, 总里程 - 起步包含里程) × 每公里价
时长费 = 总时长(分钟) × 每分钟价
夜间费 = 处于夜间时段时，加夜间附加费
动态调价 = 基础价 × (factor - 1)，factor 不超过 dynamic_max_factor
高峰溢价 = 高峰时段(早7-9点/晚17-19点) factor 自动上调至 1.3，计入动态调价费
总价 = 起步价 + 里程费 + 时长费 + 夜间费 + 动态调价
```

### 3.2 CalculateDiscount — 优惠券抵扣计算

根据优惠券计算折扣金额与实付金额（优惠券本期作为入参，不落库）。

**请求 `CalculateDiscountRequest`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| order_id | int64 | 订单ID |
| total_cents | int64 | 抵扣前订单总金额（分） |
| coupon | Coupon | 优惠券信息 |

**`Coupon` 优惠券**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| type | CouponType | 1固定金额 2折扣 |
| face_value_cents | int64 | 固定金额券面额（分） |
| discount | int32 | 折扣券折扣，80 表示 8 折 |
| threshold_cents | int64 | 使用门槛（分），0 表示无门槛 |
| max_discount_cents | int64 | 折扣券最大优惠金额（分） |

**响应 `CalculateDiscountResponse`**

| 字段 | 说明 |
| --- | --- |
| discount_amount_cents | 优惠券抵扣金额（分） |
| platform_subsidy_cents | 平台补贴金额（分） |
| payable_amount_cents | 乘客实付金额（分） |

### 3.3 SaveActualOrderPrice — 实际费用落库

行程结束时由订单模块调用，将实际费用快照写入 `order_price`（已存在则更新，不存在则新建），状态置「已确认(2)」。

**请求 `SaveActualOrderPriceRequest`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| order_id | int64 | 订单ID |
| price_rule_id | int64 | 命中的计价规则ID（可选，0 表示无） |
| actual_price_cents | int64 | 实际总价（分） |
| detail | PriceDetail | 费用明细（分），可为空（仅落总价） |

**响应 `SaveActualOrderPriceResponse`**

| 字段 | 说明 |
| --- | --- |
| success | 是否成功 |
| order_price_id | order_price 记录ID |

**调用方（成员4 · ordersvc.FinishTrip）示例**

```go
// FinishTrip 内，行程结束拿到实际里程/时长后：
_, err := priceClient.SaveActualOrderPrice(ctx, &price.SaveActualOrderPriceRequest{
    OrderId:          in.OrderId,
    PriceRuleId:      0,                        // 规则ID可选
    ActualPriceCents: in.ActualPriceCents,      // 实际总价（分）
    Detail: &price.PriceDetail{                 // 分项明细（分）
        BaseFeeCents:     baseFee,
        DistanceFeeCents: distanceFee,
        TimeFeeCents:     timeFee,
        NightFeeCents:    nightFee,
        DynamicFeeCents:  dynamicFee,
        TotalCents:       in.ActualPriceCents,
    },
})
```

> 金额单位保持「分」(int64) 透传，避免浮点换算。该接口幂等：按 `order_id` 唯一，重复调用是更新而非重复插入。

## 4. paysvc 接口

### 4.1 CreatePayment — 支付预下单

创建支付单并调第三方下单（本期为 mock），返回支付参数。

**请求 `CreatePaymentRequest`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| order_id | int64 | 订单ID |
| user_id | int64 | 支付用户ID |
| amount_cents | int64 | 支付金额（分） |
| channel | PayChannel | 支付渠道：1微信 2支付宝 3余额 |

**响应 `CreatePaymentResponse`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| payment_id | int64 | 支付单ID |
| payment_no | string | 平台支付单号 |
| transaction_id | string | 第三方支付流水号（mock） |
| pay_params | string | 支付参数（mock） |
| status | int32 | 状态：1待支付 |

### 4.2 NotifyPayment — 支付回调

处理第三方支付结果通知：验签 → 更新支付单 → 发 Kafka 事件 → 触发司机结算。

**请求 `NotifyPaymentRequest`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| payment_no | string | 平台支付单号（商户订单号） |
| trade_status | string | 交易状态：TRADE_SUCCESS / TRADE_CLOSED 等 |
| transaction_id | string | 第三方流水号 |
| sign | string | 签名 |
| sign_type | string | 签名类型 RSA2 |
| paid_at | int64 | 支付时间（Unix 秒） |
| notify_raw | string | 原始回调参数（验签用） |

**响应 `NotifyPaymentResponse`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| success | bool | 是否处理成功 |
| message | string | 处理说明 |

**处理链路**：验签 → 校验状态（仅待支付→支付成功）→ 更新支付单 → 发 `order.paid` Kafka 事件 → 调 ordersvc.GetOrder 拿 driver_id → 触发 SettleOrder 结算。

### 4.3 GetPayment — 支付查询

按支付单号（优先）或订单ID查询支付状态。

**请求 `GetPaymentRequest`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| payment_no | string | 按支付单号查（优先） |
| order_id | int64 | 或按订单ID查 |

**响应 `GetPaymentResponse`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| payment_id | int64 | 支付单ID |
| payment_no | string | 支付单号 |
| order_id | int64 | 订单ID |
| amount_cents | int64 | 支付金额（分） |
| channel | string | 支付渠道 |
| status | int32 | 1待支付 2支付成功 3支付失败 4已退款 |
| transaction_id | string | 第三方流水号 |
| refund_amount_cents | int64 | 已退款金额（分） |

### 4.4 RefundPayment — 退款

校验并执行退款，回写支付单（全额退款流转为「已退款」，部分退款保持「支付成功」）。

**请求 `RefundPaymentRequest`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| payment_no | string | 支付单号 |
| refund_amount_cents | int64 | 退款金额（分） |
| reason | string | 退款原因 |

**响应 `RefundPaymentResponse`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| success | bool | 是否成功 |
| refund_no | string | 退款单号 |
| refunded_amount_cents | int64 | 累计已退款金额（分） |

### 4.5 SettleOrder — 司机结算

计算平台抽成与司机实收，写入结算单。

**请求 `SettleOrderRequest`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| order_id | int64 | 订单ID |
| driver_id | int64 | 司机ID |
| total_amount_cents | int64 | 订单实际总金额（分） |
| commission_rate | double | 平台抽成比例（%），如 20 表示 20% |

**响应 `SettleOrderResponse`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| settlement_id | int64 | 结算单ID |
| settlement_no | string | 结算单号 |
| platform_commission_cents | int64 | 平台抽成（分） |
| driver_income_cents | int64 | 司机实收（分） |

### 4.6 支付渠道接入（支付宝手机网站支付）

模块五提供 `PayChannel` 渠道抽象与 `MockChannel`/`AlipayChannel` 两种实现，按配置平滑切换：

- **MockChannel**：默认降级实现，返回模拟流水号与支付参数（开发/测试用）。
- **AlipayChannel**：支付宝手机网站支付（`alipay.trade.wap.pay`），`CreateOrder` 生成支付跳转链接作为 `pay_params`，`Refund` 调用支付宝退款（`alipay.trade.refund`）。

**渠道选择逻辑**（`paysvc/internal/svc/service_context.go` 的 `GetChannel`）：

| 渠道名 | 支付宝配置（appId/私钥/公钥齐全） | 行为 |
| --- | --- | --- |
| `alipay` | 是 | 走真实 `AlipayChannel` |
| `alipay` | 否 | 降级 `MockChannel` |
| 其它（wechat/balance） | — | `MockChannel` |

**配置项**（`rpc/paysvc/etc/paysvc.yaml`）：

```yaml
alipay:
  appId: "9021000161684648"          # 支付宝开放平台应用ID
  privateKey: '...'                   # 应用私钥（RSA2，裸 base64 或 PEM 均可）
  alipayPublicKey: '...'              # 支付宝公钥
  gateway: https://openapi-sandbox.dl.alipaydev.com/gateway.do  # 沙箱网关
  notifyUrl: ""                       # 支付结果异步回调地址（部署后填写）
  returnUrl: ""                       # 支付完成同步跳转地址（可选）
  sandbox: true                       # 沙箱环境
```

> 当前已配置沙箱密钥，`CreatePayment` 传渠道 `alipay(2)` 时走真实下单并返回支付跳转链接；`notifyUrl` 待部署到可访问地址后填写，支付宝回调才可收到。

```
            └→ 支付失败(3)
```

## 8. 乘客端支付入口接入示例（供模块一参考）

> 乘客端属于模块一，模块五只提供参考代码，不直接改动 `api/passenger`。

乘客端网关通过 zrpc 直连 paysvc（`127.0.0.1:50054`），暴露两个 HTTP 接口：

| 路由 | 说明 | 调用 paysvc |
| --- | --- | --- |
| `POST /api/passenger/v1/pay/create` | 支付预下单 | `CreatePayment` |
| `POST /api/passenger/v1/pay/query` | 支付状态查询 | `GetPayment` |

参考接入步骤：

1. 在 `api/passenger/internal/svc/service_context.go` 注入支付客户端：

```go
import (
    "XiaoLong-Ridy/rpc/paysvc/pay"
    "github.com/zeromicro/go-zero/zrpc"
)

type ServiceContext struct {
    UserClient UserClient
    PayClient  pay.Pay // 新增
}

func NewServiceContext(userClient UserClient, payClient pay.Pay) *ServiceContext {
    return &ServiceContext{UserClient: userClient, PayClient: payClient}
}
```

2. 在 `main.go` 创建 zrpc 客户端并传入：

```go
import "github.com/zeromicro/go-zero/zrpc"

payClient := pay.NewPay(zrpc.MustNewClient(zrpc.RpcClientConf{Target: "127.0.0.1:50054"}))
server := &http.Server{
    Addr:    address,
    Handler: newHTTPHandler(svc.NewServiceContext(userClient, payClient)),
}
```

3. 新增 `types/pay.go`：

```go
package types

type CreatePaymentRequest struct {
    OrderId     int64  `json:"orderId"`
    UserId      int64  `json:"userId"`
    AmountCents int64  `json:"amountCents"`
    Channel     int32  `json:"channel"` // 1微信 2支付宝 3余额
}

type CreatePaymentResponse struct {
    PaymentId     int64  `json:"paymentId"`
    PaymentNo     string `json:"paymentNo"`
    TransactionId string `json:"transactionId"`
    PayParams     string `json:"payParams"`
    Status        int32  `json:"status"`
}

type GetPaymentRequest struct {
    PaymentNo string `json:"paymentNo"`
    OrderId   int64  `json:"orderId"`
}
```

4. 新增 `logic/pay_logic.go` 转发到 paysvc，返回前把 `amount_cents` 等字段原样透传即可。

> 金额单位保持「分」(int64) 透传，避免网关层做浮点换算。
