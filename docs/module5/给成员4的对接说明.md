# 给成员4（订单与派单模块）的对接说明

> 来自：模块五（计价与支付，分支 module5-qyx）
> 日期：2026-08-14
> 结论：支付成功后需要你配合两件事——① 实现 `GetOrder` 返回真实 `driver_id`；② 建 `order-event-consumer` 消费 `order.paid` 事件，把订单从「待支付」流转为「已完成」。

---

## 一、背景：支付回调链路里对订单模块的依赖

模块五的支付回调（`paysvc.NotifyPayment`）在支付成功后，会按下面链路流转：

```
支付宝回调 → 验签 → payment 状态改「支付成功」
  → 发 Kafka 事件 order.paid（给订单模块）
  → 调 ordersvc.GetOrder 拿 driver_id
  → 生成司机结算单（settlement）
```

这条链路依赖订单模块两处：

| # | 依赖点 | 现状 | 需要你做的事 |
| --- | --- | --- | --- |
| 1 | `ordersvc.GetOrder` | logic 是空壳（todo） | 实现它，返回真实 `driver_id`（下面给出约定） |
| 2 | 订单状态「待支付→已完成」 | ordersvc 无对应 RPC | 建 `order-event-consumer` 消费 `order.paid` 事件，把订单 4→5 |

---

## 二、事项1：实现 `GetOrder` 返回真实 driver_id

### 为什么需要

模块五回调成功后，要调 `ordersvc.GetOrder` 拿订单的 `driver_id`，否则无法生成司机结算单（不知道钱给谁）。

### 调用方式（我已经封装好，无需你改）

模块五通过 gRPC 直连你的服务（`127.0.0.1:50051`）调用：

```go
// 模块五内部封装（rpc/paysvc/internal/orderclient/order_client.go）
resp, err := orderClient.GetOrder(ctx, &proto.GetOrderRequest{OrderId: orderId})
driverId := resp.DriverId  // ← 依赖这个字段有真实值
```

### 你需要做的

把 `rpc/ordersvc/internal/logic/get_order_logic.go` 的空壳实现掉：按 `order_id` 查 `ride_order` 表，返回完整 `GetOrderResponse`，**重点是 `driver_id` 字段必须有真实值**（司机接单时写入的司机ID）。

> 提示：订单详情里 `driver_id` 来自 `AcceptOrder`（司机接单）时写入的字段。行程结束后订单已分配司机，所以 `driver_id` 一定存在，直接返回即可。

## 三、事项2：建 `order-event-consumer` 消费支付成功事件

### 为什么需要

订单状态机里「待支付(4) → 已完成(5)」这个流转，你的 ordersvc 目前没有对应 RPC。按项目 README 约定，服务间异步通过消息队列解耦，所以这个流转应该由**订单事件消费者**完成。

### 消息格式（我已发，你只需消费）

- **Topic**：`order.paid`
- **Key**：`payment_no`（支付单号）
- **Value**（JSON）：

```json
{
  "order_id": 1001,
  "payment_no": "PAY20260814120000001",
  "amount_cents": 2500,
  "paid_at": 1753065600
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| order_id | int64 | 订单ID |
| payment_no | string | 平台支付单号 |
| amount_cents | int64 | 支付金额（分） |
| paid_at | int64 | 支付时间（Unix 秒） |

### 你需要做的

参考已有的 `mq-consumer/location-consumer` 结构，新建 `mq-consumer/order-event-consumer`：

1. 订阅 topic `order.paid`
2. 反序列化上面的 JSON
3. 调用 ordersvc 内部逻辑，把 `order_id` 对应订单状态从「待支付(4)」更新为「已完成(5)」
4. （可选）写一条 `order_status_log` 状态流水

> 状态常量在 `rpc/ordersvc/proto/ordersvc.proto` 里：
> `ORDER_STATUS_WAIT_PAY = 4` → `ORDER_STATUS_COMPLETED = 5`

---

## 四、联调顺序建议

1. 你先实现 `GetOrder`（事项1）—— 这样模块五回调后能拿到司机ID
2. 再建 `order-event-consumer`（事项2）—— 这样订单状态能自动 4→5
3. 端到端联调验证：
   - `FinishTrip`（行程结束，订单变待支付 4）
   - `CreatePayment`（创建支付单）
   - 模拟支付宝回调 `NotifyPayment`（支付成功）
   - 观察：payment 状态变「支付成功」→ `order.paid` 事件发出 → 你消费后订单变「已完成(5)」→ settlement 结算单生成
