## 演示页 5 步操作（跟着走）

1. **行程配置**：默认北京快车 12.5km / 30 分钟；点「早高峰 08:00」快捷按钮。
2. **价格预估**：读出五项费用明细，重点说「高峰动态调价 = 基础价 × 0.5」，总价 **76.13 元**。
3. **优惠抵扣**：选「8 折券（满 20 元）」→ 抵扣 10 元（受上限约束）→ 实付 **40.75 元**。
4. **创建支付 + 回调**：支付宝 → 模拟收银台 → 确认支付 → 状态「待支付→支付成功」。**再点一次「模拟重复回调」演示幂等**，页面提示「已忽略重复回调」——这是核心亮点，一定演示。
5. **司机结算 + 退款**：结算 40.75 × 20% → 平台 **8.15 元** / 司机 **32.60 元**；再全额退款 → 状态变「已退款」。

> 所有金额都是真实 rule 引擎算出来的，与代码一致（见答辩稿附录 B 算例表）。

## 常见追问（完整版见答辩稿附录 B 20-Q&A）

| 高频问题 | 一句话答案 |
| --- | --- |
| 为什么金额用「分」不用「元」？ | 避免 float 漂移；DB 存 decimal(10,2)，接口用 int64 分 |
| 夜间跨天怎么判断的？ | `IsNightTime`：start 23:00 > end 05:00 时走 `cur>=st || cur<en` |
| 重复回调怎么防的？ | 事务内 `WHERE id=? AND status=待支付` 条件更新 + 已支付直接幂等返回 |
| 优惠券为什么要最高减 10 元？ | 折扣券 `MaxDiscountCents` 上限，`min(总价×20%, 上限)` |
| 和订单模块怎么协作？ | 回调后 `GetOrder` 取 driver_id + `order.paid` Kafka 事件（对接文档已给成员4） |
| AI 写了多少代码？ | 大量，但每处都跑测试验证；金额算例全部与测试对齐（详见第 15 章） |
