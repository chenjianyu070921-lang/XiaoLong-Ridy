# 模块五答辩演示页面 设计方案

> 日期：2026-08-27
> 用途：为模块五（计价与支付）答辩提供可视化演示效果，共享屏幕展示完整业务闭环。
> 背景：项目为纯 Go 微服务后端，无前端工程；模块五为纯 gRPC 服务，无浏览器页面。本方案自建轻量演示工具。

## 1. 目标

把"计价 → 优惠 → 支付 → 回调 → 结算 → 退款"整条业务链路做成可交互的可视化演示，答辩时用浏览器打开即可展示，且计算结果与真实代码 100% 一致。

## 2. 技术形态（方案 B + A 降级）

| 组成 | 路径 | 职责 |
| --- | --- | --- |
| 演示页面（单 HTML） | `docs/module5/demo/index.html` | 移动端 H5 手机框样式，交互演示全流程 |
| 真实演示服务（Go） | `rpc/pricesvc/demo/demo_server.go` | 极简 HTTP 服务，**复用模块五真实计算包** |
| 支付侧适配包 | `rpc/paysvc/demoapi/demoapi.go` | 包装 paysvc internal（渠道 mock/结算），供演示服务复用 |
| 使用说明 | `docs/module5/demo/README.md` | 启动方式与答辩注意事项 |

> 结构说明：Go 的 `internal` 规则不允许 `scripts/` 路径 import `rpc/.../internal/...`，
> 因此演示服务放在 `rpc/pricesvc/demo`（可访问计价引擎 internal/rule），
> paysvc 支付侧通过新建导出包 `demoapi` 复用。

**双模式**：
- 页面启动时 `fetch http://127.0.0.1:8787/health` 探测演示服务。
- 成功 → **真实模式**，计算全部由 Go 服务完成（调真实 `rule` 引擎），页面显示"真实计价引擎计算"标记。
- 失败 → **内置模式**，自动降级为页面内 JS 复刻的同公式计算，保证现场零依赖不翻车。

## 3. 数据一致性（复用真实代码）

演示服务直接 import 以下模块五真实实现，保证数值与线上一致：

| 能力 | 复用的真实代码 |
| --- | --- |
| 价格预估 | `rpc/pricesvc/internal/rule.Estimate` |
| 夜间判断（跨天 23:00-05:00） | `rpc/pricesvc/internal/rule.IsNightTime` |
| 高峰判断（早 7-9 / 晚 17-19） | `rpc/pricesvc/internal/rule.IsPeakTime` |
| 优惠计算 | `rpc/pricesvc/internal/rule.CalculateDiscount` |
| 结算抽成 | `rpc/paysvc/internal/rule.CalcSettlement` |
| 支付渠道（mock 流水号/支付参数格式） | `rpc/paysvc/internal/channel.NewMockChannel`（经 `demoapi.CreateMockOrder`） |

计价规则直接采用 `scripts/sql/migrate/07_price_rule_seed.sql` 的北京三条真实规则：

| 车型 | 起步价 | 起步里程 | 每公里 | 每分钟 | 夜间 23-05 | 夜间费 | 动态上限 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 特惠快车 | 8.00 | 2km | 1.80 | 0.40 | 23:00-05:00 | 5.00 | 1.20 |
| 2 快车 | 12.00 | 3km | 2.50 | 0.50 | 23:00-05:00 | 8.00 | 1.50 |
| 3 拼车 | 6.00 | 2km | 1.20 | 0.30 | 23:00-05:00 | 3.00 | 1.10 |

金额全程以「分」int64 计算，仅展示时转元，与 `common/priceutil` 约定一致。

## 4. 演示服务接口（demo_server.go，端口 8787）

| 接口 | 说明 |
| --- | --- |
| `GET /health` | 存活探测，返回 `{ok, mode:"real"}` |
| `GET /api/rules` | 返回三条北京计价规则（页面展示规则卡） |
| `POST /api/estimate` | 请求 `{cityCode, carType, distanceM, durationS, timestamp}`；返回命中规则 + 分项明细 + `isNight/isPeak` 标记 |
| `POST /api/discount` | 请求 `{totalCents, coupon}`；返回抵扣/补贴/实付 |
| `POST /api/payment/create` | 请求 `{orderId, userId, amountCents, channel}`；mock 渠道下单，返回 paymentNo/transactionId/payParams/status，服务端内存保存状态 |
| `POST /api/payment/notify` | 请求 `{paymentNo}`；模拟支付成功回调（重复回调返回幂等提示） |
| `GET /api/payment?paymentNo=` | 支付查询，返回状态 |
| `POST /api/payment/refund` | 请求 `{paymentNo, refundAmountCents, reason}`；模拟退款 |
| `POST /api/settle` | 请求 `{totalCents, commissionRate}`；返回平台抽成/司机实收 |

支付单号用 `PAY + 时间戳 + 微秒`（与 paysvc.CreatePayment.genPaymentNo 一致），退款单号 `RF + 时间戳 + 微秒`。

## 5. 演示页面交互流程

```
① 行程配置 → ② 价格预估 → ③ 优惠抵扣 → ④ 创建支付 → ⑤ 支付回调 → ⑥ 司机结算 → ⑦ 退款
```

1. **行程配置**：城市（北京默认）、车型（三选一）、里程/时长滑杆、出发时刻，快捷场景按钮（白天 10:00 / 早高峰 08:00 / 晚高峰 18:00 / 夜间跨天 23:30）。
2. **价格预估**：规则摘要卡 + 五项费用明细卡（起步/里程/时长/夜间/动态）+ 合计；夜间、高峰自动亮徽标并说明依据（`23:00-05:00` 跨天 / 早 7-9 晚 17-19）。
3. **优惠抵扣**：无券 / 5 元固定券 / 8 折券（满 20 元），展示抵扣额、平台补贴、实付。
4. **创建支付**：渠道选择（微信/支付宝/余额）→ 弹出模拟收银台弹窗 → 生成支付单（含 mock 支付参数）。
5. **支付回调**：点"模拟支付成功回调"，状态 待支付→支付成功，下发 `order.paid` 事件日志；再点一次演示**重复回调幂等**（页面提示"已忽略重复回调"）。
6. **司机结算**：按抽成率 20% 展示平台抽成 + 司机实收。
7. **退款**：演示全额退款流转为"已退款"。

底部**流水日志面板**：每一步记录接口名 + 请求参数 + 响应，可与代码对应讲解。

## 6. 视觉风格

花小猪橙色主题（`#FF6A00` 系）、移动端 H5 手机框居中、卡片式布局、现代渐变背景、各步骤进度条指引。

## 7. 验收标准

1. `go build ./rpc/pricesvc/demo/... ./rpc/paysvc/demoapi/...` 编译通过；`go test ./rpc/pricesvc/demo/...` 通过（断言计价/优惠/结算数值与 `rule` 包一致）。
2. `go run ./rpc/pricesvc/demo` 后页面真实模式连通，展示"真实计价引擎计算"。
3. 不启动 demo server，页面自动降级内置模式仍可完整演示。
4. 手工核对：北京快车 12.5km/1800s/白天 → 期望总价 = 12 + (12.5-3)×2.5 + 0.5×30 = 12+23.75+15 = 50.75 元；早高峰自动加动态费 factor=1.3。
