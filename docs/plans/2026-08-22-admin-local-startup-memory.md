# 管理后台本地启动内存优化实施计划

## 实施步骤

1. 新增 `scripts/admin-local/start.ps1`，作为管理后台本地最小服务集的唯一启动入口。
   - 仅启动 `rpc/adminsvc`、`api/admin` 和 `web/admin`。
   - 在启动前检查 `8084`、`8717`、`5173` 端口，发现冲突立即报错且不终止用户已有进程。
   - 为 Go 服务子进程设置 `GOMEMLIMIT` 与 `GOGC`，为 Node 子进程设置 `NODE_OPTIONS=--max-old-space-size=384`。
   - 管理 RPC 的数据库连接字符串仅从 `ADMINSVC_MYSQL_DSN` 环境变量读取；脚本不保存或输出任何数据库凭据。
   - 分别写入忽略的本地日志文件，并在超时后报告未成功监听的端口。

2. 新增 `scripts/admin-local/measure.ps1`，采集三个端口对应进程的 PID、进程名、工作集和私有内存。
   - 只读取本机进程与端口状态，不访问数据库，也不写业务数据。

3. 更新 `.gitignore`，忽略本地启动日志目录，避免运行产物污染工作区。

4. 验证。
   - 静态检查 PowerShell 脚本语法。
   - 执行启动脚本，确认 `8084`、`8717`、`5173` 监听。
   - 请求前端首页，确认得到 HTML。
   - 执行内存采集脚本，并在短时间后复测，确认三个进程未持续增长。
   - 不执行数据库迁移、写入或结构变更。

## 预期文件

- `scripts/admin-local/start.ps1`
- `scripts/admin-local/measure.ps1`
- `.gitignore`

## 风险控制

启动脚本不停止任何进程，不删除文件，不修改服务配置。若实际宿主机剩余虚拟内存低于三个最小进程的基础需求，脚本会给出端口与日志位置，要求释放系统内存后重试，而不会通过降低服务功能或绕过真实接口来伪造成功。
