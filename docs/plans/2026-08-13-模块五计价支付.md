# 模块五：计价与支付 实现计划

日期：2026-08-13
分支：module5-qyx
对齐参考：`rpc/ordersvc`（go-zero zrpc 标准骨架）

## 目标

1. 搭建 `rpc/pricesvc` 与 `rpc/paysvc` 两个 go-zero zrpc 服务骨架（严格对齐 ordersvc）。
2. 真正实现组长点名的三个基础接口（非空壳）：
   - `pricesvc.EstimatePrice` 行程价格预估
   - `pricesvc.CalculateDiscount` 优惠券抵扣计算
   - `paysvc.CreatePayment` 支付预下单
3. 落地 DDL 迁移脚本 + 接口文档。

## 已定技术决策

1. **价格单位**：接口与计算统一用「分」(int64)，DB 存 decimal(10,2) 元，进出一层换算（`priceutil`）。
2. **优惠券**：本期不建 coupon 表，优惠券作为 `CalculateDiscount` 入参（面额/门槛/类型），后续对接模块三优惠券配置。
3. **第三方支付**：channel 层先 mock（返回模拟支付参数/流水号），保证链路可跑通。

## 任务分解（每任务 TDD：先写失败测试 → 实现 → 变绿）

### Task 1：pricesvc 骨架
- proto：`Price` 服务，`EstimatePrice` / `CalculateDiscount` 两个 rpc
- main、config、svc（GORM + common/datasource）、model（price_rule、order_price）、server 转发壳

### Task 2：计价引擎 rule/price_engine.go（纯函数，重点单测）
- 输入：规则 + 里程/时长/是否夜间/动态倍数
- 输出：起步价、里程费、时长费、夜间费、动态调价、总价（全部「分」）
- 计价公式：
  - 里程费 = max(0, 总里程 - 起步包含里程) × 每公里价
  - 时长费 = 总时长(分) × 每分钟价
  - 夜间费 = 若当前时间落在夜间时段，加 night_surcharge
  - 动态调价 = 基础价 × (factor - 1)，factor 不超过 dynamic_max_factor

### Task 3：EstimatePrice 逻辑
- 按 city_code + car_type 查启用的 price_rule
- 调计价引擎算分项
- 写 order_price（status=预估）
- 返回分项 + 总价（分）

### Task 4：CalculateDiscount 逻辑
- 入参：order_id + 优惠券（面额/门槛/类型）
- 计算 discount_amount、platform_subsidy、payable_amount
- 更新 order_price
- 返回实付金额

### Task 5：paysvc 骨架
- proto：`Pay` 服务，`CreatePayment` rpc
- main、config、svc、model（payment、settlement）、channel 抽象 + mock、server

### Task 6：CreatePayment 逻辑
- 生成 payment_no、创建 payment 单（待支付）
- 调 channel mock 下单，回填 transaction_id
- 返回支付参数（mock）

### Task 7：编译 + 单测验证
- `go build ./...`
- `go test ./rpc/pricesvc/... ./rpc/paysvc/...`

### Task 8：DDL + 接口文档
- 迁移脚本（含 4 张表 + 初始规则数据）
- 接口文档
