# 长期伙伴业务 · 分轮次开发提示词

> 用法：把全文复制给 AI（豆包/其他），按轮次推进。每轮结束 AI 必须停下来等确认，禁止自动进入下一轮。

---

## 一、任务总览

用**分轮次**方式，把司机端的「长期伙伴」业务从零做完并落地。每轮只做一小步，做完停下等我确认，我确认后才进入下一轮。**禁止一轮做完所有事、禁止静默跳步、禁止擅自扩大范围。**

## 二、项目背景（给 AI 的上下文）

- 项目：`XiaoLong-Ridy` 网约车平台，技术栈 go-zero + gRPC + Vue3（Vite）
- 相关模块：
  - 司机 RPC：`rpc/driversvc`（gRPC 端口 50055）
  - 司机 API：`api/driver`（HTTP 端口 8082）
  - 司机前端：`web/driver`（Vite 端口 5175）
- 现有机制（必须复用，不要重造）：
  - 司机上线/心跳/位置：`rpc/driversvc/internal/onlinestore`（Redis `driver:online:{id}`）+ MySQL `driver_location`
  - 派单：`dispatchsvc`（不在司机端范围）
  - 司机端 Home 页 `web/driver/src/views/DriverHome.vue` 已有「长期伙伴」入口按钮（当前是**纯占位**，无点击事件、无后端）
- 环境：Windows/PowerShell；MySQL 在 `115.191.16.159:3306`（库 `xiaolong_ridy`）；Redis 同主机 6379

## 三、范围硬约束（违反即失败）

1. **只能改司机端代码**：司机 api / 司机 rpc / 司机前端。
2. 涉及 `dispatchsvc`、`common`、`ordersvc`、`locationsvc` 等**非司机模块**的任何改动，必须先列出来单独请示我，**批准前禁止改**。
3. 只改本轮点名的文件；没点到的文件（尤其是历史遗留、与我无关的代码）一律不动，**不要顺手"优化"无关代码**。
4. 不新增数据库 DDL 前必须先给方案（表结构、索引、是否迁移脚本、是否动现有表）让我确认。

## 四、业务定义（默认模型，第 1 轮必须与我确认后再细化）

行业通行「长期伙伴计划」模型（参考花小猪）：

- **达标条件**（示例，最终以我确认为准）：① 有从业资格证；② 当月全天或高峰期完成指定订单量；③ 近一周成交率 ≥ 阈值（如 60%）
- **权益**（示例）：进入长期伙伴池，享受派单倾斜 / 优先派单权；前端展示伙伴身份与权益
- **前端入口**：Home 页「长期伙伴」按钮接入真实页面

> 注意：这不是司机主动设置的"听单偏好"（该功能已下线）。长期伙伴是**平台侧对达标司机的激励/派单倾斜机制**。

## 五、轮次协议（每轮必须遵守）

1. **每轮开始时**：先说明本轮目标、要改的文件清单、验收方式（不超过 5 行）。
2. **每轮只做本轮范围的事**；改完必须自证：`go build` 通过 + 相关 `go test` 通过 + 给出可调用的实测步骤。
3. **每轮结束时**：停下来汇报「做了什么 / 改了哪些文件 / 验证结果 / 下一轮做什么」，等我确认后再继续。**绝不自动进入下一轮。**
4. **遇到任何歧义先问我，不猜**。尤其：业务口径、字段含义、是否动非司机模块。
5. **失败处理**：先读报错按提示修；同一动作失败两次必须换方案并说明原因。**禁止悄悄降级、禁止假装成功。**
6. **改动可回滚**：每轮改动尽量小、可独立回滚，避免把多轮风险堆在一起。

## 六、轮次划分

### 第 1 轮【业务澄清】
- 目标：与我确认「长期伙伴」的业务定义、目标司机、达标条件、权益/派单倾斜规则、前端要展示什么、验收口径。
- 产出：一份可确认的**需求清单**（表格，含：功能点 / 业务规则 / 验收标准 / 是否涉非司机端）。

### 第 2 轮【方案设计】
- 目标：给出技术方案——数据模型（是否新建表 / 复用 Redis / 新增 key）、RPC 与 API 接口清单、前端页面与入口改动点、涉及文件清单、是否需要动非司机模块。
- 产出：方案文档，等我批准后才进入第 3 轮。

### 第 3 轮【数据层 + 司机 RPC】
- 目标：按批准的方案实现数据层与司机 RPC 改动（如需），含迁移 SQL（先给我确认再执行）。
- 验收：`go build` + `go test` 通过 + 新增单测覆盖关键逻辑。

### 第 4 轮【司机 API】
- 目标：实现司机 API 的 handler / logic / types / 路由。
- 验收：编译 + 单测通过 + 用 curl 实测接口返回 code:0。

### 第 5 轮【司机前端】
- 目标：实现前端页面，并把 Home 页「长期伙伴」入口从占位接成真实跳转/交互。
- 验收：`npm run build` 通过 + 浏览器实测入口可达、页面可交互。

### 第 6 轮【联调收尾】
- 目标：端到端联调（登录 → 触发长期伙伴条件 → 查看身份/权益/派单倾斜生效）、补齐文档、清理临时文件、输出最终改动清单。
- 验收：端到端各环节 code:0 + 数据库/Redis 落库核对。
