# 司机端模块真实接口盘点

> 本文档基于代码实际定义整理（api/driver/driver.api、rpc/driversvc/proto/driversvc.proto、各 logic 实现），
> 仅记录已实现的内容，未实现/未核实的部分标注 TODO，禁止当作已实现写进答辩。

## 1. 模块边界（我负责的部分）

- `api/driver`：司机端 HTTP 网关（go-zero api），做鉴权、参数校验、聚合调用下游 RPC。
- `rpc/driversvc`：司机微服务（go-zero rpc），负责司机账号、在线状态、车辆、资质、AI 推荐分。

不属于我、仅做对接的服务（不修改其代码）：
- `ordersvc`：订单服务，接单/行程/完单的真实状态机在它那里。
- `dispatchsvc`：派单服务，派单记录列表来自它。
- Redis：在线状态权威存储（TTL 60s 保活）。

## 3. rpc/driversvc 真实 RPC 方法（来自 driversvc.proto，27 个 logic 文件对应）

### 3.1 账号
- CreateDriver / RegisterDriver / UpdateDriver / DeleteDriver（软删）/ GetDriver / GetDriverByPhone

### 3.2 在线状态（核心，Redis 权威）
- SetDriverOnline：置 online_status=1，写 Redis + 落库位置
- SetDriverOffline：置 online_status=0
- Heartbeat：刷新 Redis TTL 保活 + 多端互踢判定（device_id 不匹配返回 kicked=true）
- ReportLocation：刷新在线保活 + 落库最新经纬度
- SetDriverServiceStatus：供行程链路同步 0离线/1在线/2行程中

### 3.3 车辆
- CreateVehicle / UpdateVehicle / DeleteVehicle / GetVehicle
- 司机端 HTTP 目前开放 CreateVehicle / GetVehicle；UpdateVehicle / DeleteVehicle 仍为内部或后台链路。

### 3.4 查询与登录
- ListDrivers（分页，默认20上限100）
- Login（密码，校验手机号+明文密码+状态）
- LoginBySMS（验证码由 API 层校验，RPC 只签发 JWT）
- ListNearbyDrivers（按经纬度+半径+limit，供派单引擎，返回距离）
- GetDriverAiScore（见 3.5）

### 3.5 资质
- UploadCertification / GetCertification / ApproveCertification / RejectCertification

## 4. 关键实现事实（写实，避免答辩吹牛）

### 4.1 在线状态以 Redis 为权威
- `onlinestore` 包：key=`driver:online:{driverID}`，Hash 存 online_status/device_id/经纬度，TTL 默认 60s。
- 心跳续期 TTL 实现保活；超过 TTL 视为离线。
- MySQL `driver_location` 仅做持久化兜底与派单查询，不是权威源。
- 多端互踢：心跳时比对 `device_id`，不一致返回 `kicked=true`，由客户端强制重登。

### 4.2 AI 推荐分是加权公式，不是大模型
- 维度权重：服务分 0.45 + 取消率 0.25 + 投诉 0.15 + 当月完单 0.15。
- 各维度归一化到 [0,1] 后加权求和得 0~100 分。
- 降级：查不到服务分记录或查询异常 → `degraded=true`，回退"距离优先"策略，不阻断打车链路。
- 注意：叫"AI 推荐分"但实际是规则加权，没有训练模型/大模型推理。

### 4.3 接单/行程不在 driversvc 内
- accept/start-trip/confirm-arrive/finish-trip 由 api/driver 直接调 ordersvc。
- 行程开始/结束顺带调 driversvc.SetDriverServiceStatus 把在线状态在 1(在线) 与 2(行程中) 间切换。
- 司机端不持有订单状态机，只转发并同步自身在线状态。

### 4.4 派单列表是聚合接口
- `ListMyDispatches`：调 dispatchsvc.ListDispatchRecords（按 driver_id 分页），再逐条调 ordersvc.GetOrder 拼装订单摘要。
- 分页参数 page/pageSize/status，默认每页 10（前端约定），上限由 dispatchsvc 控制。

### 4.5 我的订单列表来自 ordersvc
- `ListMyOrders`：api/driver 只从 JWT 获取当前司机 ID，转发到 ordersvc.ListOrders(driver_id)。
- 支持 page/pageSize/status，status=0 表示全部订单，1-6 对应订单状态枚举。

## 5. 待确认 / 能力边界（实训真实状态）

- `AgentChat` 路由存在，但 logic 实现未细读，暂不写入"已实现"范畴。
- 短信验证码存储与校验位置未在本模块核实（可能在上游/中间件）。
- 多端互踢依赖 device_id 由客户端稳定上报，设备标识生成策略非本模块职责。
- 在线状态最终一致性：Redis 与 MySQL 存在短暂不一致窗口（TTL 内以 Redis 为准），属已知权衡。
