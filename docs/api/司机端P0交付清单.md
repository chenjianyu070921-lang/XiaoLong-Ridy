## 待协调 RPC 契约

### 1. 拒单

建议新增：

```proto
rpc RejectDispatch(RejectDispatchRequest) returns (RejectDispatchResponse);

message RejectDispatchRequest {
	int64 order_id = 1;
	int64 driver_id = 2;
	string reason = 3;
	string request_id = 4;
}

message RejectDispatchResponse {
	int64 order_id = 1;
	int64 driver_id = 2;
	int32 status = 3;
	int64 updated_at = 4;
}
```

### 2. 我的派单列表

当前 `ListDispatchRecords` 只有 `order_id` 条件。建议扩展请求：

```proto
message ListDispatchRecordsRequest {
	int64 order_id = 1;
	int64 driver_id = 2;
	int32 status = 3;
	int32 page = 4;
	int32 page_size = 5;
}
```

也可以新增独立的 `ListDriverDispatchRecords` RPC，避免影响已有按订单查询调用方。

### 3. dispatch.new 事件

事件 payload 至少需要：`driver_id`、`dispatch_record_id`、`order_id`、`status`、`occurred_at`、`event_id`。

司机端收到事件后不直接处理派单数据，只由前端主动调用列表接口；司机端列表逻辑再按派单记录调用 `ordersvc.GetOrder` 补充订单详情。

### 4. 验收条件

- 拒单 RPC 对重复请求具备幂等语义，并校验司机与派单记录归属。
- 司机列表查询支持 `driver_id`、分页和可选状态过滤。
- 返回记录字段与现有 `DispatchRecord` 兼容。
- dispatchsvc 完成 proto、生成代码、server 实现和联调样例后，司机端再接入真实客户端调用。

## 列表实现约定

dispatchsvc 能力补齐后，司机端将先调用派单查询 RPC，再逐条调用 `ordersvc.GetOrder`，拼装司机端新单列表；前端由 `dispatch.new` 事件触发主动拉取。

当前两个阻塞接口返回 HTTP 501、业务码 `50003`，不会伪造成功响应。未修改 dispatchsvc 或其他非司机端模块。
