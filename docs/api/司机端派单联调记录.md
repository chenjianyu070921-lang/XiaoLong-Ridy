# 司机端派单联调记录

日期：2026-08-20

## 已接入链路

- `POST /api/driver/v1/orders/reject`
  - 从 JWT 获取 `driver_id`。
  - 调用 `dispatchsvc.RejectDispatch(order_id, driver_id, reason)`。
  - 返回拒单后的 `order_id`、`driver_id`、派单状态。
- `POST /api/driver/v1/orders/dispatches`
  - 从 JWT 获取 `driver_id`。
  - 调用 `dispatchsvc.ListDispatchRecords(driver_id, status, page, page_size)`。
  - 对每条派单记录调用 `ordersvc.GetOrder(order_id)`。
  - 返回派单记录和订单摘要组合结果。

## 请求示例

```json
POST /api/driver/v1/orders/reject
{
  "orderId": 1001,
  "reason": "临时有事"
}
```

```json
POST /api/driver/v1/orders/dispatches
{
  "page": 1,
  "pageSize": 20,
  "status": 1
}
```

## 依赖配置

司机端默认连接：

- `ordersvc`: `127.0.0.1:50051`
- `dispatchsvc`: `127.0.0.1:8083`

也可使用 `ORDER_GRPC_ADDR`、`DISPATCH_GRPC_ADDR` 环境变量覆盖。

`dispatch.new` 事件不由司机 API 直接消费；它用于通知前端主动调用派单列表接口。

## 真实数据验证记录

测试司机：`driver_id=30`，手机号：`13800009996`。

测试数据：

- `ride_order.id=5`，订单号 `REAL-DRIVER-20260820-001`。
- `dispatch_record.id=4`，关联 `order_id=5`、`driver_id=30`。

验证结果：

1. `POST /orders/dispatches` 返回 `dispatch_record.id=4` 和订单摘要 `order_id=5`。
2. `POST /orders/reject` 返回 `status=3`。
3. MySQL 查询确认 `dispatch_record.id=4` 的 `status=3`、`remark=真实联调拒单`。
4. MySQL 查询确认 `ride_order.id=5` 仍为 `status=1`。

注意：本次联调使用临时本地配置将 ordersvc/dispatchsvc 指向本地 MySQL；正式配置文件未修改。
