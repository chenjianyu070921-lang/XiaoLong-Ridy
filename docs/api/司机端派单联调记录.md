# 司机端派单联调记录

## 当前范围

- `POST /api/driver/v1/orders/accept` 已调用 `ordersvc.AcceptOrder`。
- `POST /api/driver/v1/orders/confirm-arrive` 已调用 `ordersvc.ConfirmArrive`。
- `POST /api/driver/v1/orders/start-trip` 已调用 `ordersvc.StartTrip`。
- `POST /api/driver/v1/orders/finish-trip` 已调用 `ordersvc.FinishTrip`。
- `POST /api/driver/v1/orders/reject` 已完成鉴权、请求解析和参数校验，但暂不能调用下游。
- `POST /api/driver/v1/orders/dispatches` 已完成鉴权、分页请求解析和返回结构定义，但暂不能查询下游。

## 阻塞依赖

当前 `rpc/dispatchsvc/proto/dispatchsvc.proto` 只有 `DispatchOrder` 和按 `order_id` 查询的 `ListDispatchRecords`。

司机端完成拒单和“我的派单/待接单列表”还需要 dispatchsvc 提供：

- `RejectDispatch`：至少包含 `order_id`、`driver_id`、拒单原因。
- 按 `driver_id` 分页查询派单记录的 RPC，或扩展 `ListDispatchRecords` 请求。

列表补齐后，司机端逻辑应先按司机查询派单记录，再逐条调用 `ordersvc.GetOrder` 拼装司机端新单数据；由 `dispatch.new` 事件驱动前端主动拉取。

依赖未提供期间，两个接口统一返回 HTTP 501、业务码 `50003`，不会伪造成功响应。未修改 dispatchsvc 或其他模块代码。
