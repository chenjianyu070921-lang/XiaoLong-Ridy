# 管理后台运营业务表与基础接口说明

> 适用范围：模块三 `api/admin`。  
> 当前实现以 `api/admin -> rpc/adminsvc` 为统一边界；HTTP 层只负责参数解析、鉴权 token 透传和响应映射。司机审核由 `adminsvc` 调用 `driversvc`，计价规则由 `adminsvc` 调用 `pricesvc`，后台 HTTP 层不直接写业务表。

## 一、运营业务表 SQL

SQL 文件位置：

- `scripts/sql/migrate/07_admin_operation_business.sql`
- `scripts/sql/migrate/09_admin_export_audit_task.sql`

| 表名 | 用途 | 关键字段 | 说明 |
| --- | --- | --- | --- |
| `admin_complaint_work_order` | 投诉/申诉工单主表 | `work_order_no,work_order_type,status,assignee_id,version` | 支持用户投诉、订单申诉、司机处罚申诉 |
| `admin_work_order_flow` | 工单流转记录 | `work_order_id,from_status,to_status,action,operator_id` | 记录分配、跟进、仲裁、结案等动作 |
| `admin_work_order_evidence` | 工单证据 | `work_order_id,evidence_type,evidence_url,content` | 记录轨迹、录音、聊天、支付凭证等证据索引 |
| `admin_coupon_publish_record` | 优惠券发布记录 | `coupon_id,publish_version,publish_scope,status` | 记录灰度、全量、回滚等发布过程 |
| `admin_coupon_issue_task` | 发券任务 | `task_no,coupon_id,target_type,target_config,status` | 当前由 `adminsvc.IssueCoupon` 同步创建任务并写入 `user_coupon`；后续可演进为 MQ/Job 异步发放 |
| `admin_export_task` | 导出任务 | `task_no,export_type,filters,status,file_path,file_url,failure_reason,expires_at` | 当前由 `adminsvc.CreateExportTask` 创建任务，goroutine 异步生成 CSV 文件 |
| `admin_audit_outbox` | 审计补偿表 | `biz_type,biz_id,payload,status,retry_count,next_retry_at` | 司机审核等敏感操作在审计日志失败时写入补偿记录，避免跨服务状态已变更但审计丢失 |
| `risk_blacklist_hit_record` | 风控命中记录 | `target_type,target_id,scene,risk_level,hit_reason` | 记录登录、下单、派单、支付等场景命中 |

已有基础表：`admin_operation_log`、`coupon`、`user_coupon`、`promotion_activity`、`blacklist` 已在 `scripts/sql/migrate/03_admin_module.sql` 中定义。

## 二、司机资质审核接口

### 1. 审核列表

`GET /admin/v1/driver-certifications`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `keyword` | string | 否 | 司机手机号、姓名、车牌号 |
| `audit_status` | int32 | 否 | 1 待审核，2 通过，3 驳回 |
| `start_time` | string | 否 | 提交开始时间 |
| `end_time` | string | 否 | 提交结束时间 |
| `page` | int | 否 | 页码 |
| `page_size` | int | 否 | 每页数量，最大 100 |

### 2. 审核通过

`POST /admin/v1/driver-certifications/{id}/approve`

```json
{
  "remark": "资料齐全，审核通过"
}
```

处理逻辑：

| 步骤 | 说明 |
| --- | --- |
| 1 | HTTP 层透传 Bearer Token，调用 `adminsvc.ValidateSession` 校验管理员登录态 |
| 2 | HTTP 层调用 `adminsvc.ApproveDriverCertification`，不直接更新司机审核表 |
| 3 | `adminsvc` 调用 `driversvc.ApproveCertification`，由 `driversvc` 在本地事务内更新 `driver_certification.audit_status=2`、`driver.status=2`、`driver_vehicle.status=2` |
| 4 | `adminsvc` 写入 `admin_operation_log`；如果审计失败，接口返回错误并写入 `admin_audit_outbox` 补偿记录 |

### 3. 审核驳回

`POST /admin/v1/driver-certifications/{id}/reject`

```json
{
  "remark": "身份证照片不清晰，请重新上传"
}
```

处理逻辑：驳回原因必填；HTTP 层调用 `adminsvc.RejectDriverCertification`，`adminsvc` 再调用 `driversvc.RejectCertification` 更新审核记录，不激活司机和车辆；审核成功后写入 `admin_operation_log`，审计失败时写入 `admin_audit_outbox` 补偿记录。

## 三、优惠券基础接口

### 1. 优惠券模板列表

`GET /admin/v1/coupons`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `keyword` | string | 否 | 优惠券名称 |
| `type` | int32 | 否 | 1 满减券，2 折扣券，3 立减券 |
| `status` | int32 | 否 | 1 启用，3 停用 |
| `start_time` | string | 否 | 创建开始时间 |
| `end_time` | string | 否 | 创建结束时间 |
| `page` | int | 否 | 页码 |
| `page_size` | int | 否 | 每页数量 |

### 2. 新增优惠券模板

`POST /admin/v1/coupons`

```json
{
  "name": "新用户立减券",
  "type": 3,
  "face_value": "8.00",
  "discount": "1.00",
  "threshold_amount": "0.00",
  "total_count": 10000,
  "per_user_limit": 1,
  "valid_start_at": "2026-08-13 00:00:00",
  "valid_end_at": "2026-12-31 23:59:59",
  "status": 1
}
```

校验规则：

| 字段 | 规则 |
| --- | --- |
| `name` | 非空 |
| `type` | 只能为 1、2、3 |
| `status` | 当前接口接受 1 或 3，分别表示启用、停用；`POST /admin/v1/coupons/{id}/disable` 会将模板置为 3 |
| `face_value` / `discount` / `threshold_amount` | 合法非负十进制字符串 |
| `total_count` | 大于等于 0，0 表示不限量 |
| `per_user_limit` | 大于 0 |
| `valid_end_at` | 必须晚于 `valid_start_at` |

### 3. 编辑优惠券模板

`PUT /admin/v1/coupons/{id}`

请求体同新增接口。编辑只更新 `coupon` 模板表，不修改 `user_coupon` 用户券实例。

### 4. 下架优惠券模板

`POST /admin/v1/coupons/{id}/disable`

处理逻辑：HTTP 层调用 `adminsvc.DisableCoupon`，`adminsvc` 将 `coupon.status` 置为 3 并写入 `admin_operation_log`。该接口只影响优惠券模板状态，不回收已发放的 `user_coupon`。

### 5. 发放优惠券

`POST /admin/v1/coupons/{id}/issue`

```json
{
  "target_type": "explicit_users",
  "target_config": "{\"user_ids\":[1001,1002]}"
}
```

当前实现：`adminsvc.IssueCoupon` 在当前请求内校验模板、创建 `admin_coupon_issue_task`，并同步写入 `user_coupon`。返回值包含 `task_no,total_count,success_count,fail_count,status`。后续如发券规模扩大，可把该任务切到 MQ/Job 异步消费。

## 四、异常订单查询接口

`GET /admin/v1/orders/abnormal`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `abnormal_type` | string | 否 | `cancel`、`payment`、`dispatch`，为空表示全部 |
| `keyword` | string | 否 | 订单号 |
| `user_id` | int64 | 否 | 乘客 ID |
| `driver_id` | int64 | 否 | 司机 ID |
| `start_time` | string | 否 | 下单开始时间 |
| `end_time` | string | 否 | 下单结束时间 |
| `page` | int | 否 | 页码 |
| `page_size` | int | 否 | 每页数量 |

异常判定：

| 异常类型 | 判定条件 |
| --- | --- |
| `cancel` | `ride_order.status=6` 或 `cancel_reason` 非空 |
| `payment` | `payment.status IN (3,4)`，即支付失败或已退款 |
| `dispatch` | `dispatch_record.status IN (3,4,5)`，即拒绝、超时、取消 |

返回字段在订单基础字段外补充：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `abnormal_type` | string | 主异常类型 |
| `abnormal_reason` | string | 后端推导的异常原因 |
| `payment_status` | int32 | 支付状态 |
| `dispatch_status` | int32 | 派单状态 |

## 五、计价规则管理接口

计价规则当前链路为 `api/admin -> adminsvc -> pricesvc`。HTTP 层和 `adminsvc` 都不直接修改 `price_rule` 表，由 `pricesvc` 负责规则的真实读写和启停。

| 接口 | 说明 | 下游 RPC |
| --- | --- | --- |
| `GET /admin/v1/price-rules` | 计价规则列表 | `adminsvc.ListPriceRules -> pricesvc.ListPriceRules` |
| `POST /admin/v1/price-rules` | 新增计价规则 | `adminsvc.CreatePriceRule -> pricesvc.CreatePriceRule` |
| `GET /admin/v1/price-rules/{id}` | 计价规则详情 | `adminsvc.GetPriceRule -> pricesvc.GetPriceRule` |
| `PUT /admin/v1/price-rules/{id}` | 编辑计价规则 | `adminsvc.UpdatePriceRule -> pricesvc.UpdatePriceRule` |
| `POST /admin/v1/price-rules/{id}/enable` | 启用计价规则 | `adminsvc.EnablePriceRule -> pricesvc.EnablePriceRule` |
| `POST /admin/v1/price-rules/{id}/disable` | 停用计价规则 | `adminsvc.DisablePriceRule -> pricesvc.DisablePriceRule` |

## 六、导出任务接口

| 接口 | 说明 |
| --- | --- |
| `POST /admin/v1/export-tasks` | 创建导出任务，写入 `admin_export_task`，后台 goroutine 异步生成 CSV |
| `GET /admin/v1/export-tasks` | 查询导出任务列表 |
| `GET /admin/v1/export-tasks/{task_no}` | 查询导出任务详情、状态、文件路径和失败原因 |

当前导出文件默认落在 `.tmp-admin-exports`，任务状态包括 `pending/running/success/failed/canceled`。生产发布前需要按数据库发布流程执行 `09_admin_export_audit_task.sql`，代码不会自动修改线上数据库结构。
