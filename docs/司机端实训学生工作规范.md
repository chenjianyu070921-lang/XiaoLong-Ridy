（五）学生层面（整体改动）

本规范面向司机端实训学生，要求硬、可落地、能验收。每条都是行动项，标注交付物与约束规则。司机端全链路指：实名认证 → 上线听单 → 接单 → 行程服务 → 结算 → 评价。

---

1. 推行"项目-职责-难点-数据"四段式汇报模板
   - 目的：汇报最怕报喜不报忧、空喊完成，四段式逼你把难点和数据摆出来。
   - 四段定义：
     - 项目：司机端全链路一句话（认证→上线听单→接单→行程→结算→评价）。
     - 职责：你认领的具体模块，从下面六类选一或自报——实名资质、上线听单、行程状态机、钱包提现、实时推送、回家顺路。
     - 难点：这周真实卡住你的点，写清"卡了多久、卡在哪一层（前端/接口网关/服务/数据库/中间件）"。
     - 数据：亮点必须配数，司机端常用指标——接单转化率、推送到达率、核心接口平均耗时与错误率、提现零资损笔数。
   - 交付物：每周汇报文档，存 `docs/周报/`，按人分文件。
   - 约束：四段缺一段直接退回重写；数据无来源（没跑命令、没看监控）视为编造，重做。
   - 反面案例：只写"司机端功能已完成 90%"——无难点无数据，退回。

2. 每人每周输出 1 篇难点复盘（现象→根因→方案→验证 四段）
   - 目的：光解决不够，要能复现讲清，避免同一个坑踩两次。
   - 四段定义：
     - 现象：可观测表现（报错原文 / 接口无响应 / 单子一直派不出去），贴证据不贴猜测。
     - 根因：往底层挖，禁止写"网络问题""偶发"这种废话，必须定位到具体代码或配置。
     - 方案：你实际改了什么，贴改动位置（文件:行号）。
     - 验证：复现命令 + 改后结果，证明根因消除。
   - 司机端优先主题：派单池写错地理位置导致搜不到单、长连接断连靠轮询兜底、提现可超量重复、行程状态异常跃迁、心跳清错在线标记。
   - 交付物：`docs/复盘/` 下按周按人一篇。
   - 约束：无复现步骤不收；根因写"偶发/玄学"直接打回。

3. 核心机制建立"机制卡片"
   - 目的：很多人调通接口但讲不清数据流，出事不会排。
   - 司机端必画三张：
     - 上线听单时序：服务注册发现 → 缓存标记在线 → 写入地理位置派单池 → 派单引擎过滤忙碌/离线。
     - 行程状态机：待接 → 接驾 → 行程中 → 到达 → 结束 → 支付，标清每条跃迁的触发事件和幂等处理。
     - 提现防资损流程：扣减"已申请+已打款" → 校验提现密码 → 解密卡号 → 生成单据，标清资金红线。
   - 交付物：三张图（时序图/状态机图），存 `docs/机制卡片/`。
   - 约束：能脱稿讲满 5 分钟，讲不明白当场重画；卡片与代码不一致，以代码为准并改卡片。

4. 硬指标两条（每人必交）
   - 4.1 单测：每人 ≥10 个带断言的单测。
     - 司机端重点覆盖：上线逻辑（多端互踢）、派单可用性过滤（忙碌司机不进候选）、提现扣减防超量、身份证校验位、位置双写降级。
     - 交付物：测试文件 + `go test` 通过截图；断言必须验业务结论，不只验"非空"。
   - 4.2 压测报告：核心接口 P50 / P99 与错误率。
     - 司机端三接口：听单推送、接单、位置上报。
     - 交付物：压测报告（并发梯度、P50/P99、错误率），附压测命令与运行环境。
   - 约束：没报告、断言只验非空，均不算完成。

5. AI 使用三道关
   - 第一关 先自查 30 分钟：卡住先自己读代码、查日志、跑最小复现，满 30 分钟才可问 AI；自查痕迹（笔记/命令）要能展示。
   - 第二关 AI 产出必答辩：用 AI 写的代码，你要能讲清"为什么这么改、动了哪几个文件、有没有副作用"，讲不清视为没懂，重写。
   - 第三关 AI 代码过评审才入仓：AI 产出当作待测代码，必须过人工评审 + 自带单测。
   - 司机端红线：禁止用 AI 直接改派单匹配、钱包提现等资金与命门相关核心逻辑后未经评审合入；AI 改动必须附带单测。
   - 约束：违反红线该次提交打回，记一次失信。

6. 改动三件套验收
   - 每个功能交付必须齐：需求说明 + 单测跑通截图 + 机制卡片链接。
   - 约束：缺一件不验收；禁止只改代码不补测试、不写说明就提验收。

7. 命门轮值
   - 实时推送通道与地理位置派单池是司机端线上命门，出问题整条接单链路断。
   - 规则：每人轮流值守联调环境，出问题 10 分钟内复现并贴日志；超时算当班失职。
   - 交付物：轮值表 + 当班问题记录。

8. 根因调试硬闭环（工程纪律兜底）
   - 碰到缺陷不许症状修补：先复现失败（拿到失败测试或最小复现）→ 列假设 → 只修根因 → 把失败用例转回归测试留仓。
   - 约束：没复现就改代码、只加容错吞错（万能捕获异常）一律退回。

9. 事故复盘与命门指标（可用性格栅）
   - 司机端设两条命门指标：推送到达率、接单成功率；低于阈值触发复盘。
   - 复盘四段：时间线 → 影响面 → 根因 → 行动项（负责人 + 截止时间）。
   - 约束：未落行动项的复盘不关闭；行动项到期未完追踪到人。
