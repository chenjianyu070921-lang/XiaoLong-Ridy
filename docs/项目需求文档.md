# 网约车司机端项目需求文档

版本：P0 v1.0
日期：2026-08-20

## 1. 项目目标

为司机 App 提供订单接单、拒单和行程推进能力，打通司机端 HTTP API 与订单、派单服务之间的核心链路。P0 只覆盖主链路，不包含售后工单、RAG、前端页面或持久化会话扩展。

## 2. 业务范围

### 2.1 订单操作

- 接单：司机确认接受订单。
- 拒单：司机拒绝属于自己的待派单记录。
- 确认到达：司机到达乘客上车点。
- 开始行程：订单从已接单进入行程中。
- 结束行程：上报实际里程、时长和金额，订单进入待支付。

### 2.2 派单列表

司机通过列表接口查询自己的待接单记录。接口先调用 dispatchsvc 按 `driver_id` 查询派单记录，再调用 ordersvc.GetOrder 补充订单摘要。`dispatch.new` 事件只负责通知前端主动刷新，不由司机 API 直接消费。

## 3. 接口要求

所有订单操作接口使用 POST，并从 JWT 获取当前司机 ID，禁止客户端直接传入并覆盖司机身份。请求进入业务逻辑前必须完成 JSON、鉴权和参数校验；下游业务状态和归属由 RPC 服务再次校验。

## 4. 依赖服务

| 服务 | 用途 | 默认地址 |
|------|------|----------|
| driversvc | 登录、司机身份与状态 | `127.0.0.1:8080` |
| ordersvc | 订单状态推进、订单详情 | `127.0.0.1:50051` |
| dispatchsvc | 拒单、按司机查询派单记录 | `127.0.0.1:8083` |
| MySQL | 司机、订单、派单持久化 | `127.0.0.1:3306` |
| Redis | 在线状态与基础缓存 | `127.0.0.1:6379` |

## 5. 非功能要求

- 下游不可用时返回明确的 502 业务错误，不伪造成功结果。
- 列表分页限制为每页 1~100 条，默认 20 条。
- 所有关键操作可通过订单表、派单表和状态日志核查。
- 接口响应统一包含业务码、消息、数据、时间戳和 traceId。

## 6. 验收标准

- 五个订单动作均能通过司机 API 到达对应 RPC。
- 列表能返回派单记录和订单摘要组合数据。
- 拒单后 `dispatch_record.status` 从派单中变为已拒绝。
- 真实 MySQL 查询结果与接口响应一致。
