- 六人六模块协作，用户负责 **模块五：计价与支付**（rpc/pricesvc + rpc/paysvc）
- 用户 git 分支：module5-qyx

## 关键架构事实（对齐 ordersvc 参考实现）
- ordersvc 是标准 go-zero zrpc 结构：`ordersvc.go`(main) + `etc/xxx.yaml` + `proto/xxx.proto`(含已生成的 .pb.go) + `internal/{config,svc,server,model,logic}`
- `internal/config/config.go`：嵌入 `zrpc.RpcServerConf` + 自定义 Mysql/Kafka/Redis 结构
- `internal/svc/service_context.go`：用 `common/datasource.NewMysqlClient` + `common/config.MysqlConf` 初始化 GORM
- `internal/server/*_server.go`：goctl 生成，转发到 logic（`// Code generated by goctl. DO NOT EDIT.`）
- `internal/model/*.go`：GORM model + `TableName()` 方法
- `internal/logic/*.go`：每个 rpc 一个 logic，`NewXxxLogic(ctx, svcCtx)` + 方法。**ordersvc 的 logic 目前全是空壳 todo**
- 价格约定：proto 里用 `int64 xxx_cents`(分)，DB 里存 decimal(10,2) 的 float64

## common 公共包
- `common/config`：MysqlConf / RedisConf 通用配置结构
- `common/datasource`：NewMysqlClient / NewRedisClient
- `common/errorx`：OK=0 FAIL=500 PARAM=400 NOTLOG=401，NewErr/Msg
- `common/constants`：订单状态、Redis key 模板、Kafka topic
- `common/keyutil`：GenOrderID 订单号生成
- `common/response`：HTTP 统一 Result 返回（供 api 网关用）
